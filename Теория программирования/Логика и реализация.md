#SOLID #принцип_единой_ответственности

Концепция | Бизнес-логика | Реализация
--: | -- | --
Отвечает на вопрос | Что мы делаем? | Как мы это делаем?
Пример | Загрузить список фильмов с сервера | *AJAX-запрос* (axios, fetch, XMLHttpRequest) / *WebSocket* / *localStorage*
Постановщик задачи | Конечный пользователь (хочет увидеть фильмы) | Программист (например, URL-код для запроса)
Модули | Vue-компонент с визуальными данными^[Компонент просто обращается к готовой функции в модуле для извлечения данных и не имеет представления, каким способом данные извлекаются] | Модуль API для обращения к источнику данных^[Для задачи с обращением к серверу данный модуль носит название "транспортного слоя", т.к. в нем выбирается наиболее оптимальный способ обращения к источнику - т.н. "транспорт"]
Расположение | Директория с UI-компонентами | Директория с API-функциями
==Правила написания кода==: бизнес-логика и реализация не должны пересекаться в рамках одного компонента/файла. 

Таким образом, выполняется первое правило одного из пяти принципов проектирования систем [[SOLID|SOLID]] - где S означает "single responsibility" - **принцип единой ответственности**.
