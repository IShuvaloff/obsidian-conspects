**Плагины** - самостоятельные блоки кода, подключаемые к проекту автоматически^[т.е. нет необходимости вручную импортировать их в конфигурации проекта `nuxt.config.ts`], если расположены в папке `plugins` в корневом элементе. Имя плагина задается именем файла с плагином. Регистрация плагина производится с использованием системной функции `defineNuxtPlugin`:
```ts
import { createVfm } from "vue-final-modal";
export default defineNuxtPlugin((nuxtApp) => {
    nuxtApp.vueApp.use(vfm);
});
```

В случае, если мы имеем плагины во вложенных директориях папки `plugins/.../`, можно настроить их автоматический импорт аналогично автоимпорту вложенных композаблов (см. [[Композаблы Nuxt.js (composables)]]).

### **`@splidejs/vue-splide`**
Слайдер, замена swiper.js. Активно используется для проектов Nuxt.js и Vue.js. Документацию см. [здесь](https://splidejs.com/). 
   
==Установка плагина==:
   1. `npm i @splidejs/vue-splide`;
   2. Примеры использования см. в компонентах в папках `components/slider/` и `modules/feedbacks/components` в проекте TDS-Group;
   
   
==Особенности использования==:
1. чтобы **кастомизировать стили кнопок навигации и пагинации**, нужно:
	1. обернуть все слайды в компонент `SplideTrack` (импортируется из `"@splidejs/vue-splide`);
	2. добавить для тега `Splide` атрибут `:has-track="false"`, т.е. исключить установку встроенного трека;
	3. использовать опцию `classes: {...}`, внутри которой указывать наименование кастомных стилей:
  
		  ![[Pasted image 20240617215004.png]]
	
	
		* задавать свойства достаточно только для кастомных стилей, без подключения дефолтных;
		* если кнопки содержат SVG-иконки, следует сбросить их свойства ширины и высоты, а также отключить паддинг у компонентов `...arrow...`;
			  
		  ![[Pasted image 20240617182131.png]]
		  ![[Pasted image 20240617182151.png]]
  
2. чтобы кастомизировать другие стили, нужно брать исходное наименование класса - например, `.splide__list`, но смотреть, как себя ведет этот класс в DevTools - он может использоваться внутри сложного модификатора, как, например:
  
	  ![[Pasted image 20240115164829.png]]
	  
	В этом случае можно взять целиком данный модификатор и изменить его поведение:

	![[Pasted image 20240115164918.png]]
  
3. чтобы заставить слайдер работать только на определенных разрешениях экрана, а на других использовать слайды как обычные html-элементы с кастомным позиционированием, требуется использовать в опциях брейкпоинты:
	* `mediaQuery: "min/max"` - использование брейкпоинтов как mobile-first либо наоборот (по умолчанию "min");
	* `breakpoints`: описывают опции, которые действуют после (для mediaQuery="min") или до (для mediaQuery="max") указанных значений:
	  
	  ![[Pasted image 20240115165200.png]]
	  
	* в данном примере показано, что при превышении размеров экрана 960px слайдер не инициализируется, следовательно, слайды будут располагаться со свойством `display: block` один за другим. В этом случае можно кастомизировать контейнер с ними - а это класс `splide__list` (но *следует учитывать сложные модификаторы*, см. п. 2);
4. если работаем со **слайдером внутри галереи**, которая растягивается на всю ширину экрана, то обязательно нужно выставить ширину самого сплайда на 100% экрана, и содержимого слайдов на 100%. В противном случае при первичной загрузке (пока изображения еще не загружены) ширина слайдера будет равна 0 и ширина каждого слайда также будет нулевая, и следовательно при попытке выставить фокус на конкретный (не первый) слайд слайдер не сможет отыскать эту позицию^[т.к. слайдер - это лента из соединенных между собой картинок] и выставит первую фотографию, хотя в пагинации будет стоять нужный индекс:
   
   ![[Pasted image 20240227111225.png]]
   
   Подчеркивания:
	* *зеленым цветом* - ширина обязательна (объекта слайдера и все контейнеры, в котором он находится);
	* *желтым цветом* - у `SplideTrack` можно выставить ширину 100%, но она перезадается при рендеринге CSS-свойствами `splide.js`;
	* *красным цветом* - у `SplideSlide` ширина выставляется автоматически исходя из расчетов `splide.js`, поэтому задание явной ширины не будет применено;
   
5. ВОЗМОЖНО, зацикленность (карусель, *loop* в опциях слайдера) как-то влияет на правильную фокусировку нужного элемента, но это подлежит проверке.

### **`vue3-smart-captcha`**
Подключение каптчи к форме на сайте^[проверка каптчи идет следующим образом: сперва получается токен по ключу клиента на фронте, затем этот токен отправляется на сервер, далее на сервере получается токен по ключу сервера, и наконец два токена сверяются: в случае совпадения проверка считается пройденной успешно]. Порядок действий:
1. установка плагина `npm i vue3-smart-captcha`;
2. добавление (необязательно) плагина для глобальной работы каптчи:
   
   ![[Pasted image 20240219131518.png]]
   
3. подключение функции получения токена с сервера яндекса (отдельная функция `getCaptchaToken`):
   
   ![[Pasted image 20240219150330.png]]
	* здесь следует инициализировать объект каптчи, располагающийся в windows, - средства TypeScript могут не определять его, для этого нужно где-то глобально прописать в windows переменную smartCaptcha;
	* далее возвращаем промис, т.к. функция запуска каптчи не является асинхронной, и последующий вызов токена с сервера может вернуть пустышку;

В случае получения ответа интервальный цикл завершаем и возвращаем результат промиса;

		```html
		<html>  
		<head>  
		<meta http-equiv="Content-Type" content="text/html; charset=UTF-8">  
		</head>  
		<body>Verification: 8f666157dc879af2</**body**>

			meta: [{ name: 'yandex-verification', content: '8f666157dc879af2'}]
		  }
		},
		```

### **`pinia-persistedstate`**
Позволяет подключить локальные хранилища Pinia к cookies, localStorage и localSession. Представляет собой [отдельный подключаемый подмодуль](https://nuxt.com/modules/pinia-plugin-persistedstate) для хранилищ Pinia. Подключение отлично описано на сайте, но, возможно, для работы в приложении нужно будет добавить еще и плагин `pinia-persistedstate.ts`:
```ts
import { defineNuxtPlugin } from "#app";
import { PiniaPluginContext } from "pinia";
import piniaPersistedstate from "pinia-plugin-persistedstate";

export default defineNuxtPlugin((nuxtApp) => {
    nuxtApp.$pinia.use(piniaPersistedstate);
});
```

==ЗАМЕЧАНИЕ==: в большинстве случаев (особенно для авторизационных токенов) удобней использовать `useCookie('cookie-name').value` - универсальный композабл для Nuxt 3, работающий как в SSR, так и на клиенте.
