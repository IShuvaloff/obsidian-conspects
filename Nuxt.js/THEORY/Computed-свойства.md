#computed 

Вопрос **«Что делает `computed` под капотом?»** на собеседовании Middle/Senior — это проверка того, понимаете ли вы разницу между обычным методом, хуком `watch` и оптимизацией вычислений.

Если отвечать на инженерном уровне, то **`computed` — это реактивный кэширующий прокси-контейнер**, созданный для оптимизации тяжелых расчетов.

Давайте подробно разберем его анатомию, алгоритм работы и три главных отличия от других инструментов.

# 1. Как `computed` устроен внутри? (Анатомия класса)

На уровне исходного кода Vue 3, `computed` — это экземпляр класса `ComputedRefImpl`. У него внутри есть три ключевых поля:

1. **`_value` (Кэш):** Переменная, где хранится последний успешно посчитанный результат. Когда вы обращаетесь к `myComputed.value`, Vue не запускает функцию заново, он просто отдает то, что лежит в этом поле.
2. **`_dirty` (Флаг актуальности):** Булевый флаг («грязный кэш»).
    - Если `_dirty === false`, значит исходные данные не менялись, кэш актуален.
    - Если `_dirty === true`, значит исходные данные изменились, кэшу верить нельзя, нужно пересчитать.
3. **`effect` (Внутренний подписчик):** Собственный реактивный эффект `computed`-свойства, который следит за теми `ref`/`reactive` переменными, которые вы использовали внутри функции.

# 2. Подробный пошаговый алгоритм работы

Допустим, у нас есть:

ts

```ts
const hotels = ref([{ name: 'Plaza', stars: 5 }, { name: 'Hostel', stars: 2 }])
// Тяжелая фильтрация
const luxuryHotels = computed(() => hotels.value.filter(h => h.stars === 5))
```

Используйте код с осторожностью.

### Этап 1. Инициализация (Ленивый старт)

Когда вы только объявили `luxuryHotels`, Vue **НЕ запускает** фильтрацию массивов. Флаг `_dirty` изначально установлен в `true`, а поле `_value` равно `undefined`. `computed` ждет.

### Этап 2. Первое чтение (Например, при рендеринге страницы)

1. Шаблон пытается прочитать `luxuryHotels`. Срабатывает геттер `.value`.
2. Vue видит: флаг `_dirty === true`. Это сигнал: _"Пора считать!"_.
3. Запускается внутренний `effect` нашего `computed`. Он выполняет функцию фильтрации: пробегается по массиву `hotels`.
4. В момент чтения `hotels.value` срабатывает стандартный механизм **`track()`**. Переменная `hotels` записывает наш `computed` в свой список подписчиков в глобальный реестр `targetMap`.
5. Результат фильтрации записывается в `_value` (кэш), а флаг `_dirty` переключается в `false`.
6. Значение отдается в шаблон.

### Этап 3. Повторные рендеры (Магия кэширования)

Если компонент перерисовывается по какой-то другой причине (например, у вас тикают часы на экране), шаблон снова читает `luxuryHotels`.

1. Срабатывает геттер `.value`.
2. Vue проверяет флаг: `_dirty === false`.
3. Функция фильтрации массива **вообще не запускается**. Vue моментально возвращает готовое значение из поля `_value`. Процессор отдыхает.

### Этап 4. Изменение исходных данных (`hotels.value.push(...)`)

1. Массив `hotels` изменился. Срабатывает его **`trigger()`**.
2. В реестре зависимостей `targetMap` находится наш `computed`. Vue отправляет ему сигнал.
3. **Внимание:** `computed` НЕ начинает пересчитывать массив! Он ленивый. Вместо этого срабатывает кастомный планировщик (`scheduler`) внутри `computed`:
    - Флаг `_dirty` переключается обратно в `true` (кэш инвалидирован).
    - `computed` отправляет свой собственный `trigger()` дальше по цепочке — компоненту, который от него зависит.
4. Компонент встает в очередь на перерисовку. Когда очередь доходит, он снова читает `luxuryHotels.value`, видит флаг `_dirty === true`, запускает фильтрацию заново и обновляет кэш. Цикл замкнулся.

# 3. Главные отличия: Метод vs Computed vs Watch

Этот сравнительный блок — идеальный ответ на классический вопрос-добавку от тимлида.

|Критерий|Обычный метод / функция|Computed-свойство|Хук Watch|
|---|---|---|---|
|**Кэширование**|**Нет**. Пересчитывается при _каждом_ обновлении шаблона.|**Да**. Пересчитывается только при изменении исходных реактивных данных.|**Нет**. Кэша не имеет, просто реагирует на факт изменения.|
|**Синтаксис**|Вызывается со скобками: `getHotels()`|Вызывается как свойство (без скобок): `luxuryHotels`|Не вызывается в шаблоне, пишется в `<script>` для побочных эффектов.|
|**Ленивость**|Выполняется всегда, когда до него доходит очередь кода.|**Да**. Не выполнится ни разу, пока его никто не прочитает.|**Нет**. Срабатывает сразу, как только изменилась отслеживаемая переменная.|
|**Назначение**|Для обработки событий (клики, отправка форм) или мелких трансформаций текста.|Для чистой фильтрации, сортировки и преобразования данных **без изменения стейта**.|Для асинхронных действий (запросы к API, запись в LocalStorage, вызов сторонних библиотек).|

# 📥 Технический конспект по `computed` для заметок

**Вопрос интервьюера:** Как работает computed во Vue 3?

> **Ваш ответ:**  
> _«`computed` — это инструмент для декларативного вычисления данных с поддержкой кэширования. Под капотом он реализует паттерн **ленивых вычислений (Lazy Evaluation)** с помощью внутреннего флага `_dirty` и поля `_value` (кэша)._
> 
> _Он работает по следующему алгоритму:_
> 
> 1. _При создании `computed` функция не выполняется (ленивая инициализация)._
> 2. _При первом чтении `computed` проверяет флаг `_dirty`. Если он равен `true`, запускается вычисление, результат сохраняется в кэш, а флаг меняется на `false`. В этот же момент `track()` связывает исходную переменную, `computed` и компонент в единую цепочку зависимостей в глобальном реестре `targetMap`._
> 3. _При повторных чтениях, если исходные данные не менялись, `computed` моментально возвращает значение из кэша, игнорируя повторный запуск функции._
> 4. _Когда исходная реактивная переменная меняется, она через `trigger()` переключает флаг `_dirty` обратно в `true` (инвалидирует кэш) и уведомляет компонент о необходимости перерисовки. Перерасчет произойдет только тогда, когда компонент в процессе обновления снова обратится к этому `computed»_.*
