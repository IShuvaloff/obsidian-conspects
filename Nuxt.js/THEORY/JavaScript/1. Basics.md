# JavaScript Basics — Quick Refresh

> [!summary] 30-second Cheat Sheet
> - **7 primitives + object**
> - `typeof null === 'object'` — исторический баг
> - `===` — без coercion, `==` — с coercion
> - `||` — fallback для любого falsy, `??` — только для `null` / `undefined`
> - Object assignment копирует **ссылку**
> - Spread `{...obj}` — **shallow copy**
> - `structuredClone()` — deep clone многих стандартных структур
> - `map` → transform, `filter` → select, `reduce` → aggregate
> - `Set` → уникальные значения
> - `Map` → key/value, ключом может быть объект
> - `rest` → собирает, `spread` → раскрывает
> - `Object.hasOwn(obj, key)` → own property
> - `for...of` → перебор значений
> - ES Modules → named / default / dynamic import
> - Big O: `O(1)`, `O(n)`, `O(n²)`, `O(log n)`

# 1. Типы данных

## Primitive types

В JavaScript **7 примитивных типов**:

| Тип | Пример |
|---|---|
| `string` | `'hello'` |
| `number` | `42`, `NaN`, `Infinity` |
| `bigint` | `42n` |
| `boolean` | `true` |
| `undefined` | `undefined` |
| `symbol` | `Symbol('id')` |
| `null` | `null` |

Отдельно:

```text
object
```

К объектам относятся:

- plain objects
- arrays
- functions
- `Map`
- `Set`
- `Date`
- классы / экземпляры классов

> [!tip] Ментальная модель
> **Примитив** — значение само по себе.  
> **Объект** — ссылочное значение.

---

## `typeof`

```js
typeof 'hello'        // 'string'
typeof 123            // 'number'
typeof 123n           // 'bigint'
typeof true           // 'boolean'
typeof undefined      // 'undefined'
typeof Symbol()       // 'symbol'

typeof {}             // 'object'
typeof []             // 'object'
typeof function () {} // 'function'
```

> [!warning] Историческая странность
> ```js
> typeof null // 'object'
> ```

Для массива:

```js
Array.isArray(value)
```

# 2. Truthy / Falsy

Falsy-значения:

```text
false
0
-0
0n
''
null
undefined
NaN
```

Всё остальное — truthy.

Даже:

```js
[]
{}
'0'
'false'
```

→ truthy.

> [!tip] Быстрая проверка
> Если значение **не входит в короткий список falsy**, оно truthy.

---

# 3. `===` vs `==`

## Strict equality

```js
5 === '5' // false
```

`===` сравнивает **без неявного преобразования типов**.

## Loose equality

```js
5 == '5' // true
```

`==` может выполнить coercion.

> [!success] Практическое правило
> В обычном коде почти всегда используй:
> ```js
> ===
> !==
> ```

---

# 4. Coercion

JavaScript умеет неявно приводить типы.

```js
'5' + 1 // '51'
'5' - 1 // 4
```

Почему:

```text
+ со строкой
→ string concatenation

-, *, /
→ попытка привести операнды к number
```

Явные преобразования:

```js
Number('42')
String(42)
Boolean(value)
```

---

# 5. `||` vs `??`

```js
value || fallback
```

срабатывает на **любое falsy**:

```text
false
0
''
null
undefined
NaN
```

А:

```js
value ?? fallback
```

только на:

```text
null
undefined
```

Пример:

```js
0 || 100  // 100
0 ?? 100  // 0
```

> [!tip] Когда использовать `??`
> Если `0`, `false` или `''` — допустимые значения, а fallback нужен только для отсутствующего значения.

# 6. Объекты и ссылки

```js
const a = { value: 1 }
const b = a
```

Схема:

```text
a ──┐
    ├──► один объект
b ──┘
```

Поэтому:

```js
b.value = 10

a.value // 10
```

Сравнение объектов:

```js
{} === {} // false
```

Но:

```js
const a = {}
const b = a

a === b // true
```

> [!summary] Ключевая мысль
> Объекты сравниваются **по ссылке**, а не по содержимому.

# 7. Shallow Copy / Deep Copy

## Shallow copy

```js
const copy = { ...original }
```

или:

```js
const copy = Object.assign({}, original)
```

Создаётся новый верхний объект, но вложенные объекты остаются общими:

```js
const a = {
  user: {
    name: 'Ilya'
  }
}

const b = { ...a }

a !== b           // true
a.user === b.user // true
```

Схема:

```text
a ───────────────► { user: ──┐ }
                               │
                               ▼
                           { name: 'Ilya' }

b ───────────────► { user: ──┘ }
```

## Deep clone

Для многих обычных структур:

```js
structuredClone(value)
```

> [!warning]
> `structuredClone()` — не универсальная магия для абсолютно любых сущностей, но для стандартных данных намного надёжнее JSON-хаков.

# 8. Destructuring

## Object destructuring

```js
const user = {
  name: 'Ilya',
  age: 30
}

const { name, age } = user
```

Переименование:

```js
const { name: userName } = user
```

Default:

```js
const { role = 'user' } = user
```

## Array destructuring

```js
const [first, second] = items
```

Пропуск:

```js
const [, second] = items
```

# 9. Optional Chaining

```js
user?.profile?.name
```

Если промежуточное значение `null` или `undefined`:

```text
→ undefined
```

вместо ошибки.

Также:

```js
obj.method?.()
array?.[0]
```

> [!tip]
> Optional chaining проверяет именно `null` / `undefined`, а не любой falsy.

# 10. Rest / Spread

Одинаковый синтаксис:

```text
...
```

Но смысл противоположный.

## Spread → раскрыть

```js
const copy = { ...user }

const arr2 = [...arr1]

fn(...args)
```

## Rest → собрать

```js
function fn(...args) {}
```

```js
const { id, ...rest } = user
```

> [!summary]
> ```text
> spread → раскрывает
> rest   → собирает
> ```

# 11. Основные методы массивов

## `map`

Преобразование каждого элемента:

```js
const result = items.map(item => item * 2)
```

```text
input array
↓
transform every item
↓
new array
```

## `filter`

Оставить только подходящие:

```js
const active = users.filter(user => user.active)
```

## `reduce`

Свести массив к одному результату:

```js
const sum = numbers.reduce(
  (acc, value) => acc + value,
  0
)
```

Модель:

```text
map    → transform
filter → select
reduce → aggregate
```

# 13. `Set`

`Set` — коллекция уникальных значений.

```js
const set = new Set()

set.add(1)
set.add(1)

set.size // 1
```

Основные методы:

```js
set.add(value)
set.has(value)
set.delete(value)
set.clear()
```

Удаление дублей:

```js
const unique = [...new Set(items)]
```

> [!summary]
> ```text
> Set
> → unique values
> ```

# 14. `Map`

`Map` — коллекция:

```text
key → value
```

```js
const map = new Map()

map.set('name', 'Ilya')
map.get('name')
map.has('name')
map.delete('name')
```

Главное отличие от plain object:

```text
Map
→ ключом может быть любое значение

Object
→ property key обычно string / Symbol
```

Например:

```js
const user = {}

map.set(user, 'cached data')
```

Сам объект `user` является ключом.

## Практический выбор

```text
обычная структура данных
→ Object

динамическая key/value коллекция
→ Map
```

# 15. `Map` vs `Set`

| Структура | Что хранит |
|---|---|
| `Set` | уникальные значения |
| `Map` | пары `key → value` |

Мнемоника:

```text
Set → values
Map → mappings
```

# 16. Own property vs inherited property

Современный вариант:

```js
Object.hasOwn(obj, 'name')
```

Проверяет:

```text
есть ли property непосредственно в obj
```

А:

```js
'name' in obj
```

проверяет:

```text
есть ли property
в самом obj ИЛИ в prototype chain
```

> [!tip]
> Для own-property проверки предпочтительнее:
> ```js
> Object.hasOwn(obj, key)
> ```

# 17. Classes — базовое напоминание

```js
class User {
  constructor(name) {
    this.name = name
  }

  sayHello() {}
}
```

Схема:

```text
user instance
├── name              ← own state
└── [[Prototype]]
      ↓
   User.prototype
   └── sayHello       ← shared method
```

Наследование:

```js
class Admin extends User {
  constructor(name) {
    super(name)
  }
}
```

`super()` вызывает constructor родителя.

> [!warning]
> В constructor наследника нельзя использовать `this` до `super()`.

# 18. ES Modules

## Named export

```js
export const foo = 1
export function bar() {}
```

```js
import { foo, bar } from './module'
```

Переименование:

```js
import { foo as anotherFoo } from './module'
```

## Default export

```js
export default function foo() {}
```

```js
import foo from './module'
```

## Dynamic import

```js
const module = await import('./module.js')
```

Используется для:

```text
lazy loading
code splitting
conditional loading
```

# 20. Big O — минимум для frontend interview

Big O описывает, **как растёт стоимость алгоритма при росте входных данных**.

| Сложность | Модель |
|---|---|
| `O(1)` | постоянное время |
| `O(log n)` | логарифмический рост |
| `O(n)` | один проход |
| `O(n²)` | вложенные проходы |

Примеры:

```js
array[index]
```

≈ `O(1)`

```js
items.find(...)
```

в худшем случае:

```text
O(n)
```

Два вложенных цикла:

```text
O(n²)
```

Binary search:

```text
O(log n)
```

> [!tip]
> На frontend interview чаще всего важно не считать сложность идеально формально, а **увидеть лишний вложенный проход или повторный поиск по массиву**.
