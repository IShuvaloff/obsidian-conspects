**Composables** - нечто вроде полезных функций и, может быть, аналог *миксинов* из Vue 2, которые можно использовать в любой точке приложения, а в Nuxt даже без импорта. Располагаются в папке `composables/` в корне проекта либо в директории `modules/<moduleName>/composables/`.  В случае, если необходимо включить в автоматический импорт вложенные композаблы, достаточно прописать настройки в конфигурации `nuxt.config.ts`:
![[Pasted image 20241125135013.png]]

Можно установить библиотеку таких функции для Vue/Nuxt (см. установку [[Модули (modules)|модулей]]), разработанную специально для Composition API, и использовать ее функции в проекте^[но уже обязательно импортируя как модуль в приложение!]: **[VueUse](https://vueuse.org/)**.

### Важные особенности:
1. Композаблы нельзя вызывать вне системного контекста, такого как middleware, composable, setup-скрипт (компонент). Если требуется все-таки вызвать его вне контекста, следует обернуть его в функцию, и т.о. вызов композабла будет происходит в рамках работы setup. 
2. Вызов композабла в рамках миддлвара должен производиться синхронно, т.к. в противном случае выполнение может завершиться, когда текущий контекст уже перестанет существовать, и это приведет к ошибке. 

Рассмотрим ==различные композаблы Nuxt.js==:

## Получение системного контекста

Функция **[`useNuxtApp()`](https://nuxt.com/docs/api/composables/use-nuxt-app)** - аналог параметра *context* в обычных функциях Vue.js - вся требуемая информация о приложении:

```ts
const context = useNuxtApp();
```

**Пример** - утилита `useNuxtApp().$bus` для Nuxt.js, позволяющая создать ленту данных, работающих через свайп (*см. проект Завидово*);

## Получение текущего маршрута

Функция **[`useRoute()`](https://nuxt.com/docs/api/composables/use-route)**: 
1. с возможностью извлечения переданных параметров  (аналог `$route.params.id` из Vue.js) - используется в первую очередь для страниц, название которых является динамическим (см. [[Страницы (pages)]]), например, `estates/[id].vue`:

	```ts
	const route = useRoute();
	const paramId = route.params.id;
	```

2. с возможностью извлечения метаданных текущей страницы (процесс задания метаданных см. в [[Утилиты Nuxt.js (utils)|утилитах Nuxt]]):
	  
	```ts
	const metaData = route.meta;
	```
	  
3. с возможностью извлечения полного пути данного маршрута:
	  
	```ts
	const path = route.path;
	watch(() => route.path, (newv, oldv) => {...})
	```

В данном случае наблюдатель `watch` следит за построением текущего маршрута, но он должен быть вычисляемым свойством, чтобы быть реактивным, поэтому используем стрелочную функцию, а не переменную;

## Работа с маршрутизатором 

Композабл **[`useRouter()`](https://nuxt.com/docs/api/composables/use-router)**:
1. используется для управления маршрутизатором, переходом по маршрутам и т.д.;
2. переход по маршуту производится функцией `.push('pageRoute' | {name: 'pageName'})`, возвращающей Promise. Следовательно, *если требуется выполнить какие-то действия **после перехода*** (дождавшись закрытия текущей страницы), ==следует добавить `await`== перед пушем;
3. **ОБЯЗАТЕЛЬНО**: если делаем навигацию с одной страницы на другую, нужно проверить, есть ли в текущей странице query-параметры (`useRoute().query`), отвечающие за работу/отображение каких-либо глобальных данных, например, модальных окон. В случае наличия таких, в пуше нужно формировать объект с данными параметрами:
	```ts
	useRouter().push({ path: "/new-path", query: { ...useRoute().query } })
	```

## Извлечение данных по url-адресу

Асинхронная функция **[`useFetch(url, {...})`](https://nuxt.com/docs/api/composables/use-fetch#usage)** - принимает универсальный url-адрес^[и при необходимости объект с опциями] - как файла, так и сетевой - и возвращает объект, в поле data которого находится ref-ссылка на интересующий нас прокси-объект. Может использоваться как в SSR, так и в статическом [[Nuxt.js/Конфигурация проекта#^0b9bbb|рендеринге]]. Следует заметить, что данная функция является "синтаксическим сахаром" или обёрткой над двумя используемыми в ней функциями: `useAsyncData` (см. далее) и `$fetch`. Кроме того, есть поле error, которое заполняется в случае каких-либо ошибок тоже прокси-объектом. Способ использования (приведение прокси-объекта к обычному объекту через функцию [`toRaw(proxyObject)`](https://vuejs.org/api/reactivity-advanced.html#toraw)):

```ts
const { data: refProxyObj, error: refProxyErr } = await useFetch('');
const obj = toRaw(refProxyObj.value);
const err = toRaw(refProxyErr.value);
``` 
	
1. функция возвращает также boolean-поле `pending`, что означает, идет ли в данный момент загрузка. Но если мы используем `await useFetch`, то ==выполнение кода приостанавливается до момента полной загрузки данных==. Чтобы этого не происходило и чтобы появлялся смысл использования `pending`, можно использовать еще одну функцию - [**`useLazyFetch`**](https://nuxt.com/docs/api/composables/use-lazy-fetch) - в этом случае сразу после ее вызова приложение продолжит свое выполнение, но можно будет воспользоваться полем `pending`, чтобы отобразить процесс загрузки данных:

	```vue
	<script setup lang="ts">
		const { data: myObj, pending } = await useLazyFetch("...", {...});
	</script>
	```
	
	```html
	<template>
		<p>{{ pending ? "Загрузка..." : myObj }}</p>
	</template>
	```
		
2. данная функция, по наблюдениям Коли Куртеева, возвращает *статический* набор данных; 

## Более сложный вариант асинхронной загрузки данных

Функция **[`useAsyncData`](https://mydev.fun/nuxt/nuxt3-data-fetching)** - может не просто извлечь данные по url, как это делает ее обертка `useFetch`, но и использовать совершенно другую - определенную пользователем - функцию извлечения данных.
1. данная функция, по наблюдениям Коли Куртеева, возвращает *реактивный* набор данных;

## Отслеживание ширины экрана

[**`useWindowSize`**](https://vueuse.org/core/useWindowSize/) - плагин, позволяющий динамически получать изменяющуюся ширину экрана (ref-данные). Работает на клиенте, т.к. обращается к объекту `windows`. Позволяет задать стартовую ширину для случаев, когда она недоступна (возможно, при серверном рендеринге):
   
```ts
import { useWindowSize } from "@vueuse/core";

const { width: screenWidth } = useWindowSize({ initialWidth: 1920 });

// добавить брейкпоинты изменения ширины экрана (например, для ререндеринга)
const screenBreakpoint = computed(() => (screenWidth.value < 960 ? "sm" : "md"));
```

Использование useWindowSize позволяет избежать необходимости добавления обработчика `window.addEventListener('resize')`, который требуется добавлять в `onMounted`, а затем удалять в `onBeforeUnmount`, и создавать функцию-обработчик, которая отслеживала бы изменение размеров экрана.

## Работа с куками (cookies)
[**`useCookie('cookie_name')'`**](https://nuxt.com/docs/4.x/api/composables/use-cookie)) - композабл, отлично совместимый как с SSR, так и с клиентской частью, позволяет быстро создавать и удалять куки, *является реактивным*^[важно использовать его в [контексте Nuxt](https://nuxt.com/docs/4.x/guide/going-further/nuxt-app#the-nuxt-context), т.е. в плагинах, миддлварах, setup и Nuxt-хуках,  противном случае делать проверку на наличие контекста с помощью `tryUseNuxtApp()`].
##### Особенности работы
1. `useCookie` работает в двух режимах - серверном и клиентском;
2. на клиенте вызов `useCookie('cookie_name').value = 'newValue';` создает локальную куку, а при проверке значения ищет его в клиентских куках;
3. выполнение любого запроса к серверу подключает в заголовки запроса ВСЕ имеющиеся куки;
4. на сервере вызов `useCookie('cookie_name')` выполняет не поиск куков (т.к. на сервере клиентские куки не сохраняются), а проверку наличия этой куки в заголовках запроса;
5. таким образом при синхронизации между клиентом и сервером удается ==избежать ошибки гидратации==. 

## Сохранение состояния данных
[**`useState`**](https://nuxt.com/docs/api/composables/use-state) - композабл, позволяющий сохранить временное состояние данных для использования между различными страницами/компонентами сайта. [[Хранилище данных (useStates vs. Pinia)|Конструкция]]:

```ts
const state = useState('data', () => ({
	id: '123',
	name: 'Имя',
}))
```

В любом месте на сайте можно использовать данные из этого состояния:

```ts
const state = useState('data'); // получен объект с полями id и name
```

Недостатки:
1. не подходит для больших данных из-за затрат в производительности;
2. не подходит для хранения данных между сессиями, т.к. работает только в текущей сессии (в отличие от Pinia и плагина для него `pinia-plugin-persistedstate`).
==Идеально для==:
1. использования для переноса данных между страницами;
2. короткого временн*о*го промежутка использования. 

## Работа с датой, времени и часовыми поясами
[**`useDayjs`**](https://nuxt.com/modules/dayjs) - композабл, доступный после установки официального nuxt-модуля `dayjs-nuxt`. ==Порядок настройки и доступ==:
1. Установка: `npx nuxi@latest module add dayjs`;
2. Добавить модуль `dayjs-nuxt` в массив модулей в `nuxt.config.ts`;
3. Добавить глобальную конфигурацию в `nuxt.config.ts`:

```ts
export default defineNuxtConfig({
	dayjs: {
        locales: ["ru"],
        plugins: ["relativeTime", "utc", "timezone", "localizedFormat"],
        defaultLocale: "ru",
        defaultTimezone: "Europe/Moscow",
    },
});
```

4. **Доступ к модулю** предоставляется через обращение к композаблу `useDayjs()`: 
   
```ts
const dayjs = useDayjs()
```

Есть возможность установки модуля вручную через добавление плагина, формирования файла с типами dayjs, а также привязки модулей к глобальным переменным и пр.
