### Открытие имеющегося проекта

Если проект запускается в `https://`, то могут возникнуть [проблемы с ключами SSL](https://yandex.ru/video/preview/3299602757102136059). В этом случае скачанные ключи могут не помочь, придется генерировать их самому. Для этого нужно:
1. скачать и установить утилиту [OpenSSL](https://slproweb.com/products/Win32OpenSSL.html) (обязательно полную 64-битную версию, для разработчиков);
2. прописать адрес `openssl.exe` в переменных среды (если не добавлен автоматически);
3. создать новые ключи, например, командой:
	   
	```
	openssl req -newkey rsa:2048 -nodes -keyout key.pem -x509 -days 365 -out cert.pem
	```

4. названия файлов в команде выше можно изменять: по умолчанию это ключ `key.pem` и `cert.pem`;
5. сертификаты добавляются в текущую папку, нужно переместить их в отдельную папку с ssl-сертификатами;
6. для запуска защищенного https-сайта нужно использовать параметры в package.json:
	   
   ![[Pasted image 20231101200019.png]]

7. **важно добавить эти же ключи на сервере**, чтобы CORS-политика не блокировала запросы с нашего источника.
8. Запуск проекта в режиме разработки:
	1. для **приложения Nuxt 3**: 
		* производится командой `npm run dev` (для запуска на локальном устройстве) и `npm run dev -- --host` (для доступа также и с мобильных устройств по IP-адресу компьютера):

			```shell
			npm run dev
			npm run dev -- --host
			```

		* запуск на мобильном устройстве можно обеспечить также путем добавления в команду запуска `--host` в файле `package.json` - в этом случае запуск приложения и локально, и для внешних устройств будет доступен командой `npm run dev`:
			
			```json
			{
				"scripts": {
					...
					"dev": "nuxt dev --host",
					...
				}
			}
			```

	2. для **приложения Nuxt 2**:
		* в настройках `nuxt.config.ts` нужно явно указать хост 0.0.0.0:
		  
		  ![[Pasted image 20240328155617.png]]
		  
		* запуск проекта осуществлять через `npm run dev`;
		* доступ с телефона по IP-адресу компьютера;

9. Сборка проекта и запуск собранной версии на локальном хосте - команда `npm run build`. В этом случае идет очистка и перенастройка всех файлов в папке `.nuxt` в корне проекта, а затем предлагается запустить команду `node .output/server/index.mjs`? после чего предоставляется рабочая ссылка на [http://localhost:PORT](http://localhost:PORT) (*строго с http вместо https!*):
   
   ![[Pasted image 20240206104928.png]]

10. Сборка проекта в виде статических файлов (html/js/css) для выгрузки на простой сервер - `npm run generate`. В этом случае в корне проекта создается папка `/dist` с нужным контентом.

		```ts
		import { resolve } from "path";
		export default defineNuxtConfig({
		    alias: {
		        modules: resolve(__dirname, "modules/"),
		    },
		    ...
		});
		```
		
	* подключение массива файлов стилей, отрабатывающих в указанном порядке (в случае, если подключается плагин с пре- или постпроцессорами, они должны быть также подключены в отдельном блоке с [[Плагины (plugins)|плагинами]]):

		```ts
		export default defineNuxtConfig({
			css: [
				"~/assets/css/main.css", 
				"vue-final-modal/style.css",
			],
		})
		```
		
	* серверный либо статический рендеринг (по умолчанию универсальный, т.е. движок Nuxt сам решает, в каких случаях какой использовать):

		```ts
		export default defineNuxtConfig({
			ssr: true,
		})
		```
		
	* подключение или отключение инструмента Nuxt DevTools^[спецблок на странице с отслеживанием состояния приложения Nuxt]:
	  
	  ![[Pasted image 20240522163848.png|200]]
	  
		```ts
		export default defineNuxtConfig({
			devtools: {
		        enabled: true,
		    },
		})
		```
		
	* отключение ошибки при генерации страницы в случае, если из серверного рендеринга на клиентский происходит передача данных, которые невозможно [сериализовать](https://github.com/nuxt/nuxt/issues/20889) (функции) - в этом случае ошибка будет отображаться в виде предупреждения, и ==использовать этот способ в боевом режиме не рекомендуется==:
	  
		```ts
		export default defineNuxtConfig({
		  experimental: {
		    renderJsonPayloads: false
		  }
		})
		```
	  
2.  ==[Настройка заголовков страниц](https://nuxt.com/docs/getting-started/seo-meta)==^[указанный вариант с использованием `useHead` в `app.vue` почему-то не работает в программе "Завидово", приходится делать по схеме, указанной далее]:
	* главный заголовок выставлен в виде функции titleTemplate в композабле `useSeoMeta` в **главном макете** (*layout*) страницы в файле `src/layouts/default.vue` - при этом функция вызывается в скрипте `setup`:
	```ts
	useSeoMeta({
		titleTemplate: (pageTitle) => {
			return "Курорт Завидово" + (pageTitle ? ` - ${pageTitle}` : "");
		}
	})
	```
	* для того, чтобы заголовок страницы был динамическим, используем функцию `titleTemplate`, куда передаем параметр заголовка `title` каждой создаваемой страницы, - в этом случае он будет добавляться в конце содержимого текущего шаблона;
	* заголовки страниц выставляются аналогичным образом в композабле `useSeoMeta` на **страницах** в папке `src/modules/<moduleName>/pages/<pageName>.vue`, но с использованием свойства title в скрипте `setup`:
	```ts
	const title = "Гольф-обучение";
	useSeoMeta({ title });
	```
