Структура данных и сравнение с Options API:

Характеристика | Composition API | Options API
---: | :--- | :---
Инициализация^[показывается функция или объект, внутри которого и содержится все остальное в компоненте (см. далее в таблице)] | `setup(...) { ... }` | `defineComponent({ ... })`
Входные данные | специальная опция **setup**^[отрабатывает до инициализации data, computed, methods в компоненте, поэтому использовать в ней `this` нельзя, нужно только передавать в нее параметры; возвращаемые же значения будут доступны уже в остальных частях компонента] в функции инициализации: `setup(props)` | объект с данными: `props: { prop1: { type: String }}`
Использование входных данных для наблюдения - первый параметр функции *setup* - **props** | деструктуризация входных данных через функцию **toRefs**^[полученные преобразованные данные становятся реактивными и их можно оборачивать в `watch` (см. далее в таблице)]: `const { prop1, prop2 } = toRefs(props);`, либо функцию **toRef**, если нужно получить только одно поле из всех входных данных: `const { prop1 } = toRef(props, 'prop1');` | по умолчанию: `watch: { prop1() {...}}`
Использование контекста во входных параметрах - второй параметр опции *setup* - **context** (нереактивный объект) | <ul><li>объект атрибутов: `context.attrs`;</li><li>объект слотов: `context.slots`;</li><li>функция генерации событий: `context.emit`;</li><li>функция публичных свойств: `context.expose`</li></ul> | <ul><li>`$attrs`</li><li>`$slots`</li><li>`$emit`</li></ul> 
Реактивные данные^[данные, значения которых могут изменяться динамически, будучи связанными с интерфейсом] | <ul><li>константа в функции **ref**^[функция-обёртка, превращающая простые, передающиеся по значению переменные, в объекты, которые в свою очередь уже передаются по ссылке, а потому реактивность сохраняется]:<br>`const var1 = ref('value');`</li><li>объект в функции **reactive**^[для поддержания реактивности, если объект будет возвращен из функции `setup`]:</br>`const obj = reactive({ title: 'Заголовок' });`</li></ul> | функция, возвращающая объект: `data() { return { var1: 'value' };` 
Обращение к реактивным данным | по специальному полю **value** переменной (*кроме использования в шаблонах*^[в шаблоне можно брать значение самой переменной `var1`. Но если `var1` - *объект, обернутый в `ref`*, то для получения его свойств каждое свойство следует уже развернуть с использованием value - `var1.prop1.value`!]): `var1.value` | напрямую: `this.var1`
Создание вычисляемых свойств | специальная функция **computed**^[возвращает также реактивные данные]: `const myCompVar = computed(() => {...});` | объект с функциями `computed: { myCompVar() {...}}`
Создание функций-действий | функциональное выражение: `const myFunc = (...) => {...}` | объект с функциями: `methods: { myFunc() {...}}`
Наблюдение за изменением данных | функция **watch**: `watch(var1, (newValue, oldValue) => {...});` | опция: `watch: { var1 (newValue, oldValue) {...}}`
Хуки жизненного цикла | аналогичные функциям Options API, но с добавлением в начало ***on***: `onMounted(myFunc)` | функции `mounted()`, `created()` и т.д.
Возможность использовать данные снаружи | через ключевое слово **return**: `return { var1, myFunc }` | по умолчанию всё

==Дополнительные особенности==:
1. Все функции следует импортировать из `vue`: 
   `import { ref, toRefs, watch, computed, onMounted } from 'vue';`
2. Можно смысловые блоки содержимого `setup` вынести в отдельные функции композиции в одноименных файлах (при этом структура таких функций будет аналогична содержимому `setup`, и возвращаемые данные будут доступны во всех последующих частях кода в компоненте):
   
	```js
	import {...} from 'vue';
	
	export default function useBlockInfo( prop1, ... ){
		...
		return { data1, func1 };
	}
	```

3. В случае декомпозиции вынесенные в отдельные файлы смысловые функции можно импортировать в исходный компонент и добавить внутрь функции `setup`:
   
	```js
	import useBlockInfo from '@/composables/useBlockInfo';
	import { toRefs } from 'vue';
	
	export default {
		...,
		setup(props) {
			...
			const { prop1 } = toRefs(props);
			const { data1, func1 } = useBlockInfo(prop1);
			...
			return { data1, func1, ... };
		},
		...
	}
	```

4. Можно добавить "синтаксический сахар" и в теге скрипта разместить атрибут setup: **`<script setup>`** - тогда все содержимое тега фактически и будет являться той же самой функцией, только с мелкими отличиями:
	1. `defineProps<{...}>()` - внутри аналогично объекту в Options API, вместо списка свойств в параметрах setup при классическом использовании. Судя по всему, объявленные внутри свойства можно будет использовать в html-коде, но для использования в блоке `<script>` нужно все-таки извлечь свойства в отдельную переменную и обращаться к свойствам через объект `props`:

		```ts
		const props = defineProps<{
		    card: IDutyCard;
		}>();
		
		console.log(props.card);
		```
