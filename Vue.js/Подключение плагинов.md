Пусть **X** - некий требуемый плагин/модуль/библиотека, который необходимо использовать в приложении Vue. Как интегрировать его?

Порядок действий:
1. Определить, предоставляет ли X данные, которые нужно реактивно обновлять?
	1. да^[Пример: **Apollo** - один из клиентов GraphQL. Фишка последнего в том, что когда один запрос обновляет данные, все остальные запросы, использующие эти данные, также автоматически обновляются. Это и есть реактивность] => ==однозначно== ищем в **npm** пакет, реализующий реактивную связку Vue и X. Чаще всего такие надстройки носят названия, начинающиеся с *vue-X*;
	2. нет^[Примеры: **axios** - просто получение данных по запросу с сервера; **websocket**/**socket.io** - туннель/библиотека по работе с туннелем - для отправки и приема сообщений. Оба примера хотя и работают через промисы, но в них нет никаких данных, которые требовалось бы реактивно обновлять. Это всего лишь инструменты для получения данных из третьих мест ] => переходим к п.2;
2. Определить, может ли X быть визуальным компонентом?
	1. да^[Пример: **Google Maps** - хотя и не содержит конкретных данных, подлежащих реактивному обновлению, но является вполне себе визуальным, поэтому, возможно, стоит поискать какой-либо плагин типа vue-googlemaps или что-то подобное] => ==возможно==, стоит найти в **npm** пакет, реализующий реактивную связку Vue и X - *vue-X*. Но только при условии, что такой пакет реализует все требуемые нами условия. В противном случае проще и быстрее будет использовать стандартные js-плагин/модуль/библиотеку - X;
	2. нет^[Пример: тот же **axios**]=> переходим к п.3;
3. Подключаем X исключительно средствами JavaScript (работаем с ним как с обычным JS-плагином/модулем/библиотекой). В большинстве случаев это предпочтительней всего, особенно при создании и использовании библиотек каких-либо компонентов^[Почему? Потому что если ваш компонент полагается/зависит от нескольких внешних плагинов/модулей/библиотек, то простой копипастинг этих компонентов между проектами без дополнительной установки нужных плагинов приведет к ошибкам].
4. Интересные примеры плагинов:
	* **`Day.js`** - обработка дат и времени;
5. Особенности работы плагина **`node-sass`** - данный плагин требовал наличия на компьютере Python и/или Visual Studio, т.к. это требовалось для преобразования кода sass в корректный css. Однако, поддержка его завершена, поэтому на текущий момент достаточно плагина **`sass`** и сопутствующих плагинов (для фреймворков Vue/Nuxt). Порядок действий:
	1. удалить запись `node-sass` из зависимостей `package.json`;
	2. удалить папку `node_modules`;
	3. произвести установку `npm i`;
	4. установить плагины `sass` и дополнительные (при необходимости). 
	5. ==может получиться так==, что 3-й пункт не пройдет без предварительной установки sass. В этом случае можно сперва поставить sass, посмотреть, что за текущая версия установлена, а затем оставив запись в `package.json`, выполнить пункты с 2 по 3.
