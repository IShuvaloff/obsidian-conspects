## 📚 Что я изучил
1. Наиболее известные антипаттерны:
	- *засорение глобального пространства имен своими переменными;*
	- *передача строк внутрь setTimeout/setInterval вместо функций;*
	- *изменение прототипа класса Object (страшнейший антипаттерн);*
	- *использование инлайн-скриптов в html-коде (негибкий подход);*
	- *использование `document.write` вместо `document.createElement` и др.*
2. паттерны динамического импорта:
	- ***Import on interaction** - импорт при совершении действия, например, по событию click*;
	- ***Import on Visibility** - ленивый импорт при появлении объекта на экране (viewport). Используется [InteractionObserver API](https://developer.mozilla.org/ru/docs/Web/API/Intersection_Observer_API)*
3. отличия модулей от классических скриптов:
	- *модули парсятся только один раз (обычные скрипты каждый раз при импорте);*
	- *автоматически обрабатываются после полного рендеринга DOM (defer);*
	- *модули обособлены друг от друга (scoped) и переиспользуемы;*
	- *автоматически исключаются сборщиками, если не используются в проекте.*
4. главные отличия **библиотеки** от **фреймворка**:
	- библиотеки *больше применимы для мелких и средних веб-приложений* (хотя React настолько развит, что на нем написан Facebook);
	- библиотеки *требуют большей координации между разработчиками внутри команды* (т.к. нет четкой *архитектуры проекта*, как во фреймворке);
	- PWA (*Progressive Web App*) - веб-сайт, обладающий функциями нативного приложения: офлайн, пуш-уведомления, установка на устройства и т.д.
	- *прогрессивный фреймворк* - система, которая позволяет подключать свои части постепенно по мере необходимости (реактивность, хранилища, роутер, SSR и т.д.);
5. принципы проектирования:
	- ***разделение ответственности*** (разбивка крупных блоков на более мелкие);
	- *композиция над наследованием* (использование одних объектов внутри других вместо наследования. Для Vue это добавление одних компонентов в другие);
	- ***принцип единой ответственности*** (обособленность операций в рамках функции/компонента - только одно действие);
	- **инкапсуляция** (объединение стилей, кода, функционала внутри "черных ящиков", наподобие компонентов в Vue);
	- KIC (***keep it clean***):
		- смысловая группировка фрагментов кода;
		- очистка памяти, удаление ненужных ссылок и обработчиков событий (во Vue это хуки `onMounted` и `onBeforeUnmount`);
	- DRY (***don't repeat yourself***) - избегать дублирования кода, абстрагировав его в отдельные модули или компоненты;
	- KISS (***keep it simple & short***) - лучше мелкие и простые компоненты (без чрезмерности), чем одна большая и сложная система;
	- ***code for the next*** (написание легкого и поддерживаемого в будущем кода).
6. варианты *структурированного архитектурного кода*: модульность, SOLID, компонентный подход (Vue/Nuxt);
7. ==ПАТТЕРНЫ==:
	- **Синглтон** - единожды созданный объект на весь проект. Для инкапсуляции логики, используемой глобально (см. [[🧭 День 1 — Архитектурное мышление и базовые паттерны#1. **Синглтон-класс**|синглтон-класс]] и [[🧭 День 1 — Архитектурное мышление и базовые паттерны#2. **Синглтон-объект** + **Инъекция зависимостей**|синглтон-объект]]);
	- **Dependency injection** (Инъекция зависимостей) - в объекте/классе использовать данные из других объектов не через импорт, а через получение этих объектов в качестве свойств конструктора/параметра (см. [[🧭 День 1 — Архитектурное мышление и базовые паттерны#2. **Синглтон-объект** + **Инъекция зависимостей**|пример]]);
	- **Factory** (Фабрика) - создание новых объектов не напрямую (`new Class()`), а с помощью функции с передачей внутрь параметров. Внутри функции уже создается нужный класс в зависимости от значения параметра (см. [[🧭 День 1 — Архитектурное мышление и базовые паттерны#4. **Прокси** + **Фабрика** + **Декоратор**|пример]]);
	- **Модуль** - создание файла, содержащего *настоящие приватные* переменные/методы (т.к. не экспортируются) и экспортируемого по дефолту объекта, внутри которого переменные и методы (имеющие доступ к приватным, объявленным ВНЕ объекта) являются уже публичными. В качестве приватной переменной может выступать WeekMap (см. [[🧭 День 1 — Архитектурное мышление и базовые паттерны#5. **Модуль**|пример]]);
	- **Observer** (Наблюдатель) - [шина событий](https://www.npmjs.com/package/mitt), диспетчер для обработки всех событий. Имеет функцию регистрации обработчика события, удаление обработчика событий (со стороны наблюдателей) и функцию вызова события (со стороны объекта наблюдения) (см. [[🧭 День 1 — Архитектурное мышление и базовые паттерны#3. **Диспетчер событий**|пример]]);
	- **Command** (Команда) - создание инвокера, который собирает команды в справочник для выполнения, а затем в зависимости от команды и переданных данных производит вызов нужного действия;
	- **Proxy** - прослойка, позволяющая получить доступ к ресурсу с предварительной промежуточной обработкой и функциональностью (например, добавление реактивности, *работа только с внутренними данными*). Активно используется [класс](https://learn.javascript.ru/proxy) `new Proxy(target, handler)` (см. [[🧭 День 1 — Архитектурное мышление и базовые паттерны#4. **Прокси** + **Фабрика** + **Декоратор**|пример]]);
	- **Декоратор** - аналог прокси, но расширяет внутреннюю обработку внешней функциональностью (например, логирование процессов) (см. [[🧭 День 1 — Архитектурное мышление и базовые паттерны#4. **Прокси** + **Фабрика** + **Декоратор**|пример]]). Нечто похожее выполняет во Vue `middleware`, а также оборачивание одного компонента в другой с целью обработки входных данных;
	- **Façade** (Фасад) - еще один аналог прокси и декоратора, упрощая получение данных из источника (скрывая всю сложность и упрощая интерфейс в пределах фасада). Простейшие примеры фасадов - библиотеки *mitt*, *axios* и др;
	- **Callback** (Обратный вызов) - эффективен, если требуется выполнение кода *callback*, после завершения *асинхронной операции*. Функция коллбэка передается внутрь операции (похоже на инъекцию зависимостей);
	- **Promise** - оборачивание функциональности в [промис](https://learn.javascript.ru/promise-basics) `new Promise((resolve, reject) => {...})` для добавления асинхронности. Позволяет более гибко использовать коллбэки с помощью ключевых слов `then`/`catch`.

8. **Objects / Maps / WeakMaps**:

	Характеристика | Object | Map | WeakMap
	-- | -- | -- | --
	**Типы ключей** | `String`, `Symbol` | *Любые* (в т.ч. объекты/функции) | *Только* объекты/функции
	**Порядок ключей**|Не гарантирован | Всегда по порядку вставки |Не применимо
	**Методы**|`Object.keys()`, `Object.values()`, `Object.entries()`|Богатый API (`set`, `get`, `has`, `delete`, `clear`, `size`) | Минимальный API (`set`, `get`, `has`, `delete`)
	**Перебор**| Сложнее (через методы `Object.*`) | Лёгкий (`for...of`) | Нельзя + нет свойства `size`^[т.к. элементы в любой момент могут быть удалены сборщиком мусора]
	**Прототип**|Да (лишние свойства^[например, [Function: toString] - ключ из прототипа]) | Нет | Нет
	**JSON.stringify**| Работает сразу | Сперва преобразовать Map в Object^[с помощью `Object.fromEntries(map.entries())`] | Нет
	**Особенность**|Структуры данных^[создание модели с неизменяемой структурой данных и строковые ключи - например, профиля пользователя]| Универсальная коллекция^[динамическое содержимое, разные типы ключей, важен порядок заполнения] | Удобен в паттерне "Модуль"^[удобен для привязки приватных данных к объекту, см. [[🧭 День 1 — Архитектурное мышление и базовые паттерны#5. **Модуль** + **Модуль через WeakMap**]]], автоочистка сборщиком мусора^[когда на ключ не остается ни одной внешней ссылки]
	**Формула для памяти**|==*Структура (модель)*== |==*Коллекция (ключ-значение любого типа)*==|*==Привязка к объекту без утечек памяти==*

## 🧠 Инсайты
- избегать использования *антипаттернов*
- лучше импортировать содержимое модуля как объект с присваиванием ему имени (класса): `import * as Staff from '...';`
- динамический импорт оптимальней при отсутствии необходимости предварительной загрузки требуемых данных, синтаксис `let module = await import('...');`;
- файлы *.mjs* - те же самые .js, но обрабатываются как модульные в процессе runtime;
- для кэширования компонентов, которые исчезают и появляются на экране (например, вкладки), можно использовать [встроенный Vue-компонент](https://vuejs.org/api/built-in-components.html) `<KeepAlive>`;
- избегать создания во Vue монолитных компонентов с несколькими разными функциями;
- лучше вести документацию по проекту с описанием процессов и действий (**.md**);

### 2. **Синглтон-объект** + **Инъекция зависимостей** 
Упрощенно, без проверок - для внедрения зависимостей во всех требуемых местах проекта:
```js
const dependencyService = {                  // создание синглтона-объекта
  dependencies: {},                          // словарь зависимостей
  provide(name, dependency) {
	this.dependencies[name] = dependency;    // заполнение словаря
	return this;                             // для создания цепочки присвоения
  }, 
  inject(name) {
	return this.dependencies[name] ?? null;  // получение зависимости по имени
  } 
}; 
export default dependencyService;
```

### 3. **Диспетчер событий** 
Наблюдатель, выполнен в виде **синглтона**:
```js
class ObserverPattern {
  constructor() {
	this.events = {};                                   
  }

  on(event_name, fn = () => {}) {                         
	if (!this.events[event_name]) this.events[event_name] = [];
	this.events[event_name].push(fn);                      
  }

  emit(event_name, data) {
	if (!this.events[event_name]) return;
	for (let i = 0, l = this.events[event_name].length; i < l; i++)
	  this.events[event_name][i](data);
  }

  off(event_name, fn) {
	const i = this.events[event_name].indexOf(fn);
	if (i > -1) this.events[event_name].splice(i, 1)
  }
}
```
---
```js
import dispatcher from '...';
// использование со стороны наблюдателя:
const handler = (e) => console.log(e);
dispatcher.on('eventName', handler);
// использование со стороны объекта наблюдения:
dispatcher.emit(eventName, 'Информация');
// очистка мусора (KIC)
dispatcher.off('eventName', handler);
```

### 4. **Прокси** + **Фабрика** + **Декоратор**
Производит авторасчет температуры внутри себя:
```js
class Temperature {
	value = { celsius: 0, fahrenheit: 32 };
	handler = {
		set(target, key, value) {
			if (!["celsius", "fahrenheit"].includes(key)) return false;
			target[key] = value;
			switch (key) {
				case "celsius":
					target.fahrenheit = Temperature.calculateFahrenheit(value);
					break;
				case "fahrenheit":
					target.celsius = Temperature.calculateCelsius(value);
					break;
			}
			
			logs.push('Новый лог'); // функция декоратора
			return true;
		},
		get(target, key) {
			return target[key];
		},
	};

	constructor(value) { // дефолтное значение в цельсиях
		const result = new Proxy(this.value, this.handler);
		result.celsius = value || 0; 
		return result;
	}
	// фабрика
	static value(value) {
		return new Temperature(value);
	}
	static calculateCelsius(fahrenheit) {
		return Math.round(((fahrenheit - 32) / 1.8) * 10) / 10;
	}
	static calculateFahrenheit(celsius) {
		return celsius * 1.8 + 32;
	}
}  
 
// использование:
const temp1 = new Temperature(23);
const temp2 = new Temperature(-4);
const temp3 = Temperature.value();
temp3.fahrenheit = 45;

let logs = []; // внешний функционал
```

### 5. **Модуль** + **Модуль через WeakMap**
```js
// файл module.js (простой модуль)
let privateVar = 0;
export default {
	publicVar: 'Hello',
	publicFunc() {
		return ++privateVar;
	}
}
```

```js
// файл module.js (модуль с приватными свойствами и автоочисткой памяти - см. учебник Addy Osmani "Learning JavaScript Design Patterns", стр. 48)
let _counter = new WeakMap(); 
class Module { 
	constructor() { 
		_counter.set(this, 0); 
	} 
	incrementCounter() { 
		let counter = _counter.get(this); 
		counter++; 
		_counter.set(this, counter); 
		return _counter.get(this); 
	} resetCounter() { 
		console.log(`counter value prior to reset: ${_counter.get(this)}`); 
		_counter.set(this, 0); 
	} 
} 

// внешний файл
const testModule = new Module(); // пока есть этот объект, работа будет вестись именно в нем. Если ссылка на него пропадет, он будет удален из WeakMap

testModule.incrementCounter(); 
testModule.resetCounter();
```
