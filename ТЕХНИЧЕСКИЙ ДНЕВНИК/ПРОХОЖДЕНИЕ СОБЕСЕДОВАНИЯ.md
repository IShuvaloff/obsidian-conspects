### ❓ Вопрос 2 (уже тех интервью)

##### 👉 Представь:

- Ты делаешь проект на Nuxt 3 с API.  
- Нужно организовать работу с сервером.

**Как ты будешь строить слой работы с API?**

Расскажи:

- где будут запросы
- как будешь обрабатывать ошибки
- как переиспользовать код

##### 💬 Ответ

> **Я стараюсь выстраивать слой работы с API как отдельный абстрактный уровень.**
> 
> В Nuxt 3 я обычно создаю отдельный слой, например `/api` или composables, где разделяю запросы по доменам — например `user.api.ts`, `orders.api.ts`.
> 
> Для выполнения запросов использую единый HTTP-клиент (например, обёртку над `$fetch` или axios), где настраиваю:
> 
> - базовый URL
> - заголовки
> - обработку ошибок
> - при необходимости — interceptors
> 
> Ошибки стараюсь обрабатывать централизованно, а не в каждом запросе. Например:
> 
> - глобально обрабатываю 401 (редирект на логин)
> - логирую ошибки
> - нормализую формат ответа
> 
> Сами API-функции возвращают либо типизированные данные, либо пробрасывают ошибку выше, чтобы уже на уровне бизнес-логики решать, как её обработать.
> 
> Далее эти API используются в Pinia или composables, где уже находится бизнес-логика — например, загрузка данных, кеширование, состояние загрузки.
> 
> Таким образом:
> 
> - API слой отвечает только за транспорт
> - Pinia/composables — за логику и состояние
