#routing

## Базовая маршрутизация
==Схема==:
1. `/routes/web.php` - подключение маршрутов (редирект на контроллеры);
2. `/app/Http/Controllers/...` - размещение php-файлов контроллеров, которые используют модели для получения данных^[в папке `/app/Http` располагаются все классы, связанные с HTTP: controllers, middlewares, requests и т.д.];
3. `/app/Models/...` - размещение php-файлов моделей (классов для работы с БД);
4. `Inertia::render(...)` - рендеринг vue-страниц с передачей параметров.

---
> [!ЦЕЛИ]
> Допустим, имеем страницу `/resources/js/pages/List.vue` со списком объектов (**URL**: `/list`) и страницу `/resources/js/pages/Item.vue` с информацией об объекте (**URL**: `/list/slug`, где slug - это код объекта). Клик по объекту из списка должен привести к открытию страницы объекта с добавление в URL-строку кода этого объекта. 
> 
> На странице объекта нам нужно извлечь информацию по нему и обеспечить работу в режимах: 
> * SSR - полная перезагрузка данных на сервере из-за браузерной перезагрузки либо перехода на страницу по прямой ссылке (чтобы работала эта функция, *SSR должен быть включен в настройках билда* `composer.json, scripts`);
> * SPA - навигация между страницами на клиенте (без полной перезагрузки страницы).
---

==Подробный порядок операций перехода *со страницы списка на страницу объекта*==:
1. запрос из файла `web.php` переводится на контроллер с помощью вызова^[запрос любого маршрута в проекте Laravel **ВСЕГДА** идет через `web.php` и следом через контроллер, выполняя все его действия, в т.ч. выгружая заново данные (следом во всех vue-страницах *props* реактивно изменяются). Т.е. **маршрутизация в проекте Laravel не клиентская, а всегда серверная**! На клиенте только перерисовывается страница (как в обычных SPA-проектах);]:
   
   ```php
   Route::get('/list/{slug}', [ItemController::class, 'show']);
   ```

	- выполняем запрос по адресу направляем его в класс контроллера в функцию `show(...)`;
	- значение `slug` извлекается из URL-адреса автоматически и подставляется параметром в вызов функции `show($param_name)` (название параметра может быть любым);
	- если это первая загрузка (==SSR/прямая ссылка==), первым делом данные загружаются на сервере и лишь затем отправляются на клиент (серверный рендеринг);
	- если это клиентская навигация (==SPA==), движок *Inertia* перехватывает клик по линку, делает AJAX-запрос в Laravel^[это любой запрос в данной экосистеме Laravel, он проходит обязательно через запрограммированные в папке `/routes` маршруты `Route::...`], но страница не релодится целиком, а перерисовывает свой контент, при этом в самом начале *props* либо пустые (если еще не были ранее загружены), либо неактуальные^[в это время можно показывать лоадеры/скелетоны, пока *props* не изменятся реактивно;];
	- при клиентской навигации контекст клиентских хранилищ *Pinia*/*vuex* сохраняется, поэтому можно кэшировать загруженный один раз данные на клиенте и отображать, пока на сервере в контроллере идёт перезагрузка;
	- т.о. **повторная выгрузка данных (partial/full reload) в хуках (`onMounted`)не требуется**, т.к. переход по маршруту всегда идет через сервер в приложениях Laravel (что заново выгружает данные и обновляет реактивно *props* на привязанной странице), но можно привязать переменную `loading` к существованию значения в нужном параметре в props:
		```ts
		const loading = computed(() => props.item);
		// или
		const loading = computed(() => usePage().props.value.item);
		```
   
2. в файле контроллера `ItemController.php` нужно предварительно получить все требуемые для работы страницы данные, допустим, категории и объекты:
   
   ```php
   class ItemController ... {
	   show($slug) {
		   $item = Item::where('id', $slug)->firstOrFail();
		   $category = Category::where('id', $item->category_id)->first();
	   }
   }
   ```

	- обращаемся к моделям Item и Category - это спец. классы, где настроена возможность создания и выполнения SQL-запросов к базе данных и привязанным к моделям таблицам;
	- `where(...)` - извлекает те строки, для которых id (первый параметр) равен второму параметру;
	- `firstOrFail()` - берем первый результат в выдаче либо, при отсутствии, Laravel инициирует ошибку и редирект на страницу 404;
	- `first()` - берем первый результат в выдаче, либо `null`;
	- все запросы в php синхронные, поэтому страница не начнет отрисовываться прежде, чем загрузятся все нужные данные;
   
3. рендеринг страницы и передача файлов внутрь, делается двумя способами: 
	- через  [[Функции-хэлперы#Глобальные функции-хелперы|хелпер]]:
	  
	  ```php
	  return inertia('Item', ['item' => $item, 'category' => $category]);
	  ```
	  
	- с помощью [[3. Сервисы и фасады#Фасад|фасада]]:
	  
	  ```php
	  use Inertia\Inertia;
	  return Inertia::render('Item', ['item' => $item, 'category' => $category]);
	  ```
	  
3. использование данных на странице `Item.vue`:
	- с помощью композабла **`usePage()`** (динамический список параметров):
		```ts
		import { usePage } from '@inertiajs/vue3';
		const page = usePage(); // reactive-объект
		const item = computed(() => page.props.value.item);
		const category = computed(() => page.props.value.category);
		```

	- с помощью **`defineProps`** (в стиле vue.js, особенно при использовании TypeScript, если список параметров заранее определен):

		```ts
		const props = defineProps<{ 
			item: any, 
			category: any 
		}>();
		```

4. использование [Laravel-маршрутизатора](https://inertiajs.ru/manual-visits) **`router`** для управления фоновыми AJAX-запросами без перезагрузки страницы (если необходимо, например, обновить данные на уже открытой странице без полной перезагрузки и для отображения лоадера). Поддерживает функции:
	1. `visit( '/url', { method: 'post', data: {...} }` - универсальный способ выполнения запроса;
	2. `reload` (перезагрузка данных на текущей странице, в том числе частичная^[параметр `only` получает массив только тех элементов из *props*, которые нужно перевыгрузить, в нашем случае только *item*, без *category*, это процесс называется *"partial reload"*]):
		```ts
		import { router } from '@inertiajs/vue3';
		const loading = ref(false);
		const reloadItem = () => {
			loading.value = true;
			router.reload({
				only: ['item'],
				onSuccess: () => (loading.value = false),
			});
		}
		```
	3. `get( '/url', { search: 'Строка' }, {...}` (получение данных с сервера) - второй параметр это query-параметры, третий параметр это настройки. Пример набора настроек для всех подобных запросов:
		```json
		{
			preserveScroll: true, // сохранить позицию скролла
			preserveState: ['item'], // сохранить содержание формы
			replace: false, // заменить history.replaceState вместо pushState
			only: ['item', 'messages'], // перезагрузить только часть пропсов
			onSuccess: () => alert('Обновлено!'),
			onError: () => alert('Ошибка!'),
			// headers, data, method и иные
		})
		
		```
	1. `post`, `put`, `delete` (отправка форм на сервер с обратной связью). Здесь синтаксис аналогичен методу *get*, но вторым параметром идет тело запроса (*body*):
		```ts
		import { router } from '@inertiajs/vue3'
		
		const formData = {
			name: 'John',
			email: 'john@example.com',
		}
		
		router.post('/users', formData, {
			preserveScroll: true,
			onSuccess: () => alert('Форма успешно отправлена!'),
			onError: (errors) => console.log('Ошибка:', errors),
		})
		```
		
	Переменные в **props**/**usePage** обновятся реактивно, как при обычной навигации;

## Кэширование данных
Т.к. *все запросы идут через Laravel*, то кэширование на сервере более предпочтительно, чем на клиенте, поскольку только это уменьшит нагрузку. Если требуется исключить серверный запрос, а использовать только клиентский, нужно перехватывать клик и не отправлять его на сервер по умолчанию, но это **костыль**. 
### Серверный кэш
Делается в контроллере с помощью [[Функции-хэлперы#Глобальные функции-хелперы|хелпера]]:
```php
$item = Cache::remember("item_{$slug}", 60, function () use ($slug) {
	return Item::where('slug', $slug)->firstOrFail();
});
```
- здесь обновление происходит каждые 60 минут;
- выгрузка данных ускоряется (меньше нагрузка на БД);
- клиентское кэширование необязательно.
Пока 60 минут не истекли, обращения к БД и обновления данных не будет! Возможна ==принудительная очистка== кэша (инвалидизация):
1. добавить маршрут в `web.php` для очистки кэша:
	```php
	Route::post('/list/{slug}/cache/forget', [ItemCacheController::class, 'forget'])
		->name('item.cache.forget');
	```
2. создать контроллер управления кэшем `ItemCacheController.php` и добавить в него метод `forget`:
	1. создание файла контроллера: `php artisan make:controller ItemCacheController`;
	2. добавление функции очистки:
		```php
		namespace App\Http\Controllers;
		use Illuminate\Support\Facades\Cache;
		use Illuminate\Http\RedirectResponse;
		
		class ItemCacheController extends Controller {
		    public function forget(string $slug): RedirectResponse {
		        Cache::forget("item_{$slug}");
		
		        // Можно использовать флеш-сообщение для UI
		        return back()->with('success', "Кэш для {$slug} очищен");
		    }
		}
		```
3. добавить запрос на очистку кэше на фронте:
	```ts
	const clearCache = () => { 
		if (!slug.value) return; 
		router.post(
			route('item.cache.forget', { slug: slug.value }), 
			// либо вместо ключа берем '/list/${slug.value}/cache/forget'
			{}, 
			{ 
				preserveScroll: true, 
				onSuccess: () => { 
					// после инвалидации — перезагрузим только нужный prop 
					router.reload({ only: ['item'];
				}
			}
		);
	};
	```
4. флэшбэк с сервера - возвращает на фронт определенную информацию, которую можно использовать для лоадеров, алертов, обработки ошибок, перехватывая через `usePage()`:

	```ts
	const page = usePage();
	const result = computed(() => page.props.flash.success);
	```

Принудительная инвалидизация полезна для вызова после UPDATE/DELETE-операций с объектом. Вызов роута очистки кэша желательно защитить миддлваром, проверяющим авторизацию пользователя. 
### Клиентский кэш
Хранение данные в локальном хранилище, например, Pinia. 
- при первом получении данных из *props* сохранять их в кэш;
- при возврате на страницу с кэшированными данными сразу их отрисовывать для ускорения UI-отрисовки (в хуке `onMounted`), и обновлять после обновления *props* (в результате отработки контроллера), а также при принудительном обновлении (по нажатию кнопки);
```ts
import { useItemsStore } from '@/stores/items'
const itemsStore = useItemsStore()

onMounted(() => {
  if (itemsStore.has(props.item.id)) {
    item.value = itemsStore.get(props.item.id)
  } else {
    item.value = props.item
    itemsStore.save(props.item.id, props.item)
  }
})
```
