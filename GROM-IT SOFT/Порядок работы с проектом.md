
1. Для работы использовать только отдельную ветку **`dev`**;
2. В рамках выполнения задачи можно делать несколько коммитов, но при слиянии должен быть создан только один коммит;
3. В рамках задачи изменения добавляются через, подтверждаются, выкладываются на сервер *в свою же ветку*, а затем на сайте GitLab в репозитории создается **Merge Request** с указанием подписанта, которому предстоит проверять:
	1. `git add src/.../filename`;
	2. `git commit -m 'комментарии'`;
	3. `git push origin dev`;
	4. [GitLab](https://gitlab.com/zavidovo-lp/site-frontend) -> выбрать ветку `dev` -> кнопка "Merge Request" -> выбрать в качестве подписанта Рому^[slipgrom];
4. После успешного подтверждения слияния наставником в своей ветке в VSCode выполнить `git pull origin main`, что позволит синхронизировать ветки разработчика и родителя.
5. Если в рамках работы требуется **обратиться к бэкенду** за какими-то изменениями в API:
	1. если сотрудник тоже работает над этим проектом - можно в личном чате;
	2. если сотрудник занят другим проектом, то лучше создать задачу в [таск-трекере](https://tracker.gromitsoft.ru/backend/gromit/simpletracker/tasks/kanban);
