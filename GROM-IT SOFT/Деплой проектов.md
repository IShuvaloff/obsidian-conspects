## Процесс доступа к серверу клиента и выгрузка данных из GitLab
Для деплоя используются программы:
1. **OpenVPN** - способ задания внешнего IP со своего компьютера для управления деплоем на компьютерах заказчиков:
	1. файл инсталляции и конфигурация проекта лежат в папке `D:\Загрузки\OpenVPN`, конфигурация в файле `offprice_gromit.ovpn`;
	2. для подключения конфигурации нужно открыть приложение и импортировать конфигурацию, подключение произойдет автоматически;
	3. программа работает в трее;
2. **XShell** - программа подключения к серверам заказчика:
	1. установочник лежит в папке `D:\Загрузки`, скачать можно с [сайта](https://www.netsarang.com/ru/free-for-home-school/)
	2. после запуска требуется создать сессию для подключения к нужному серверу (если еще не создана):
	   
	   ![[Pasted image 20240423112508.png]]
	   
	3. Вся информация о серверах заказчиков и способах подключения к ним лежит [здесь](https://wiki.gromitsoft.ru/):
		* выбираем клиента, например, TDS Group;
		* ищем у него ip-адрес, логин и пароль для подключения к серверу^[для Linux вставка осуществляется через *Shift + Ins*], например для TDS Group такие:
		  
		  ![[Pasted image 20240423113823.png]]
		  
		* в XShell при создании сессии вносим информацию во вкладки:
			* СОЕДИНЕНИЕ: имя + хост (ip-адрес);
			* АУТЕНТИФИКАЦИЯ: логин + пароль от сервера по введенному ip-адресу;
			* ПРОБРОС: снимаем галку X11-перенаправления;
		* соединяемся с сервером;
		* вводим в консоль команду `sudo su`^[команды Linux] - выдать себе расширенные права администратора для управления файлами на сервере;
		* вводим^[для удаления ошибочных символов используется комбинация Ctrl + BackSpace] команду `mc` для открытия файлового менеджера сервера:
		  
		  ![[Pasted image 20240423114249.png]]
		  
		* нужно выйти в корень репозитория и войти в директорию `/var/www`;
		* выбрать нужный сайт - в нашем случае `/oootds.group`;
		* выбрать нужную папку (`api`/`front`) - мы получили доступ к репозиторию нашего проекта на сервере заказчика;
		* нажимаем *Ctrl + O* - таким образом мы в консоли выбрали нужную директорию;
		* далее управление осуществляется через обычные команды git. Чтобы перетянуть изменения с [нашего репозитория](https://git.gromitsoft.ru/tds/front) в репозиторий заказчика, нужно ввести команду `git pull`. Данные для пулла уже находятся в репозитории в папке `.git`. ==Если потребуется впервые залить репозиторий, то сперва клонируем его (аналогично  тому, как делаем это у себя на компьютере)==;
		* **итоговая сборка проекта** осуществляется командой `npm run build`;
		* затем запустить команду `pm2 start`^[[*PM2*](https://habr.com/ru/articles/480670/) - менеджер процессов, используемый для оптимизации сборки большого проекта на Node.js]. Если выдается ошибка доступа к файлу экосистемы, следует проверить:
			1. проект поддерживает модули, т.е. в `package.json` установлено свойство `type: module;`;
			2. файл экосистемы существует в корне проекта - `ecosystem.config.js` - и  написан в формате CommonES (`module.exports = ...`), который несовместим с нашим проектом, написанном в формате ES (более современный, использующий команды `import`/`export`);
			3. для решения проблемы совместимости - переименование разрешения файла экосистемы на `ecosystem.config.cjs` (постфикс .cjs^[убедиться, что при редактировании разрешения добавлена не русская, а английская буква]), отправка изменений на сервер, пересборка проекта и запуск менеджера процессов с явным указанием рабочего файла экосистемы `pm2 start ecosystem.config.cjs`;
			   
			      ![[Pasted image 20240530201836.png|400]]
				   ![[Pasted image 20240530201924.png|400]]
			   
		* опционально можно запустить команду `pm2 update` для обновления менеджера;
		* для *отслеживания консольных сообщений* запустить команду `pm2 monit`;
		* для *полного перезапуска всех проектов на сервере* запустить команду `pm2 restart all`;
	1. если не хватает прав для пулла данных или сборки проекта (==*Permission Denied*==), перейти в корень клиентского репозитория и запустить команду `chown -R root:root .` и только после этого произвести пулл/сборку проекта (см. п.3). 

## Создание нового репозитория на сервере клиента и подключение GitLab
Порядок действий:
1. создаем на [GitLab](https://git.gromitsoft.ru/) новый репозиторий для подключения к серверу клиента;
2. в программе Shell (см. пред. подраздел) создать новый репозиторий в папке `/var/www`, куда будет импортироваться содержимое репозитория на GitLab;
3. в созданную директорию в Shell скопировать файл **`ecosystem.config.js`**^[на скриншоте панель с цифрами в нижней части экрана - это команды, вызываемые нажатием клавиш F1, F2 и т.д.]
   
   ![[Pasted image 20240530200219.png]]

	* слева обычно открываем директорию новую, а справа исходную;
	* в правой части выбираем нужный файл и нажимаем F5;
	* в открывшемся окне выбираем целевую папку, проверяем исходный файл и жмем ОК:
	  
	  ![[Pasted image 20240530200511.png]]
	  
1. заходим в новосозданную директорию будущего проекта и выполняем поочередно команды из новосозданного репозитория в GitLab для заливки файлов клиентского сервера в GitLab^[ссылки обязательно указываем абсолютные, несмотря на то, что в гитлабе они выглядят иначе]:
	1. `git init --initial-branch=main` - инициализация пустого git-репозитория с главной ветвью *main*;
	2. `git remote add origin https://git.gromitsoft.ru/offprice/collab-nuxt-3.git` - устанавливаем соединение с удаленным git-репозиторием (сюда и вписываем абсолютную ссылку), выставляем его по умолчанию (origin):
	   
	   ![[Pasted image 20240530214501.png|300]]
	   
	3. `git add .` - добавляем все имеющееся содержимое папки на клиентском сервере в гит (сейчас там только файл экосистемы);
	4. `git commit -m 'initial commit'` - коммитим данные;
	5. `git push --set-upstream origin main` - отправляем закоммиченные данные на git-сервер в ветку *main*, вводя требуемые логин и пароль от моего аккаунта (*ishuvaloff*/*Piw1jGz8*);
2. на своем компьютере создаем папку нового проекта, клонируем туда содержимое новосозданного репозитория на GitLab;
3. **вносим коррективы в файл экосистемы** - меняем наименование *name* (т.к. это уникальное имя, используемое на сервере для каждого из проектов) и скрипт *script* на:
   
   ![[Pasted image 20240530201836.png|400]]
   ![[Pasted image 20240530201924.png|400]]

	***ВАЖНОЕ ЗАМЕЧАНИЕ***:
	* проект поддерживает модули, т.е. в `package.json` установлено свойство `type: module;`;
	* файл написан в формате CommonES (`module.exports = ...`), который несовместим с проектом, написанном в формате ES (более современный, использующий команды `import`/`export`);
	* решение проблемы - переименование разрешения файла экосистемы на `ecosystem.config.cjs` (постфикс .cjs^[убедиться, что при редактировании разрешения добавлена не русская, а английская буква]), отправка изменений на сервер, пересборка проекта и запуск менеджера процессов с явным указанием рабочего файла экосистемы `pm2 start ecosystem.config.cjs`;
   
4. **разворачиваем шаблон приложения Nuxt 3** в локальном репозитории и далее работаем стандартно - ==изменения, коммиты, пуш на гитлаб, пулл на клиента, деплой на клиенте==.
