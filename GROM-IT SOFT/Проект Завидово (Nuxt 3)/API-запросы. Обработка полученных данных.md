Полученные данные следует обработать и вернуть. ==Особенности возврата данных==:
1. Запросы к API-серверу (*content.gromit*/*content.zavidovo*, см. [[Пароли]]) всегда возвращают **стандартный набор json-данных**, среди которых имеется свойства *data* и *meta*. Информация по нему: 
	1. расположен в корне в файле `core/response.interface.ts`;
	2. объединен в интерфейс-дженерик **`ApiResponseList`**, возвращающий `data` - любой тип данных `T` (его необходимо будет передать внутрь дженерика) и мета-информацию по запросу в свойстве `meta`:

		![[Pasted image 20231117175355.png|500]]

	3. внутрь дженерика передаем тип данных, который будет возвращаться в свойстве `data` (именно он подставляется вместо типа `Т`):
	   
		![[Pasted image 20231117175734.png]]
	   
	4. данный интерфейс должен использоваться по умолчанию всегда, когда мы обращаемся к `useHttp`, т.к. это прямое обращение к API-серверу, т.е. формат возвращаемых данных одинаков и обговорен заранее:

		![[Pasted image 20231117175840.png|600]]

2. После получения стандартного набора данных и возврата его из `useHttp` требуется этот набор данных как-то обработать и привести к единому виду для использования этого единообразия во всех местах проекта. Для этого используется аналогичный интерфейс объекта с пагинацией:
	1. расположен в корне в файле  `core/response.interface.ts`;
	2. объединен в интерфейс-дженерик **`DataPaginationResponse`**, возвращающий `data` - любой тип данных `T` (его необходимо будет передать внутрь дженерика) и информацию о пагинации данного набора в свойстве `pagination`:

		![[Pasted image 20231117212551.png|350]]

	3. пагинация (свойство `pagination`) формируется в результате создания объекта класса **`Pagination`**: 
		1. интерфейс по нему расположен в корне в файле `core/pagination-manager.ts` и называется **`DataPaginationResponse`** - **TODO**: надо бы перенести в файл с интерфейсами:

			![[Pasted image 20231117212947.png|250]]

		2. класс для создания объектов пагинации расположен в том же файле `core/pagination-manager.ts` и называется **`PaginationManager`**: 

			```ts
			export class PaginationManager {...}
			```
		
		3. класс имеет два статических свойства, одно из которых - создание базовой (нулевой) пагинации, а второе - ==создание пагинации с учетом уже непосредственной мета-информации== в объекте возвращенных по API-запросу данных - эта пагинация очень похожа на поле `meta` в интерфейсе `ApiResponseList` из п.1, но *их важно не путать*:

			![[Pasted image 20231117213634.png|450]]

	6. все запросы с серверов информация по которым разбита на страницы требуется обрабатывать с учетом данного класса и возвращать данные уже в виде объекта `Pagination`;
	7. следует **ПРАВИЛЬНО УКАЗЫВАТЬ ПРАВИЛЬНЫЙ ТИП ДАННЫХ В ФУНКЦИИ**, внутри которой происходит обработка API-запроса - не `ApiResponseList`, а **`DataPaginationResponse`**, либо его производные/наследники (см. далее);

3. Если возвращаемых данных внутри стандартного интерфейса `DataPaginationResponse` мало, можно ==расширить тип возвращаемых данных== до какого-нибудь кастомного, например, `DataPaginationListCategories` с передачей внутрь возвращаемого типа данных:
