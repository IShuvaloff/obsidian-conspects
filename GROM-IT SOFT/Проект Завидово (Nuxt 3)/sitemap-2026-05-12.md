## 3. Приоритет сопоставления роутов (обязательно)

Порядок классификации URL:

1. Точные статические пути.
2. Специфические динамические шаблоны.
3. Fallback-шаблон `/{slug}` только если не совпало ни одно правило выше.

Ограничения для `/{slug}`:

- только один сегмент пути после корня;
- не должен пересекаться со статическими путями;
- не должен пересекаться с результатами специфических динамических шаблонов.

## 4. Фильтры включения (обязательно)

Включать URL только если все условия истинны:

- `published = true`;
- `indexable = true`;
- `noindex = false`;
- `auth_required = false`;
- `deleted = false`;
- `canonical` указывает на этот же URL;
- код ответа страницы 200;
- `slug`/`path` не пустой и валидный.

Исключать URL, если истинно хотя бы одно условие:

- техническая/приватная/сервисная страница;
- URL содержит query-параметры;
- duplicate canonical path;
- fallback `/{slug}` дублирует URL, уже попавший под другой роут;
- URL закрыт robots/noindex политикой.

## 5. Правила каноникализации

- Использовать URL в нижнем регистре.
- Использовать единую политику слеша (без дублей с и без завершающего слеша).
- Удалять query-параметры из URL sitemap.
- Отдавать абсолютные URL с префиксом https://zavidovo.com.

## 6. Рекомендуемый payload от backend для генератора sitemap

```json
{
    "path": "/novosti/primer-sluga",
    "lastmod": "2026-05-12",
    "changefreq": "weekly",
    "priority": 0.7,
    "indexable": true,
    "source": "news"
}
```

Минимально обязательные поля: path, indexable.

## 7. Примечания

- Фронтовый роут /sitemap.xml работает как proxy. Логика генерации и агрегация URL должны быть на backend.
- Роут loyalty (/programma-loyalnosti) сейчас отключен во frontend-модуле и не должен включаться.
