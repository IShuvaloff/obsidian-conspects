#promise-all #useHttp #promise-all-settled

Для API-запросов, загрузка которых проводится постранично, иногда удобно страница за страницей выгружать данные. Если нужно выгрузить сразу несколько страниц подряд, проще использовать одновременную асинхронную загрузку через **`Promise.all`**.

==Порядок запросов== внутри *асинхронной функции-контейнера*:
1. формирование массива адресов страниц или параметров запроса:
	```ts
	const pages = [{name: 'Стр. 2', slug: 2}, {name: 'Стр. 4', slug: 4}];
	```
2. формирование^[пополнение списка может быть поэтапным, через `arr.push(...)`] списка [[API-данные. Варианты запросов на получение данных|API-запросов]] для асинхронной обработки^[в этом случае возвращаются только функции, без старта их обработки!]:
	```ts
	const requests = pages.map((item) => {
		useHttp<ApiResponseList<IDutyCardResponse[]>>("/activities", {
			params: { page: item.slug, per_page: 10 }
		})
	});
	```
3. обработка запроса - в `res` будет выведет массив результатов каждого запроса: 
	```ts
	const res = await Promise.all(requests).map((item) => {
		return toRaw(item.data.value) as ApiResponseList; // map - это уже субъективно
	})
	```
4. **ВАЖНО**: даже если отдельные запросы будут идти разное время, порядок результатов в итоговом массиве будет такой, каков порядок запросов внутри параметра `Promise.all`!
5. обработку запросов можно вести по-всякому, в данном контексте это преобразование реактивного прокси-объекта в обычный объект `ApiResponseList` (подробности см. здесь - [[Композаблы Nuxt.js (composables)#^0704a2|Функции Nuxt.js (composables) - извлечение данных по url-адресу]]).

## Ошибки при отработке запросов
Для `Promise.all` характерно то, что ==в случае ошибки в одном из запросов, отработка остальных пресекается==! 
Для исправления этого косяка используется [функция `Promise.allSettled`](https://learn.javascript.ru/promise-api#promise-allsettled):
1. общий результат запрос - массив с результатами каждого запроса;
1. каждый запрос возвращает результат, отличающийся в зависимости от успеха/ошибки;
2. в случае ошибки получаем объект со статусом `rejected` и данными в поле `reason`;
3. в случае успеха получаем объект со статусом `fulfilled` и полем с данными в виде предполагаемого результата API-запроса.
