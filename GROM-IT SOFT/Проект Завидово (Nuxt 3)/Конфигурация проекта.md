2. ==Создание фильтров==:
	1. загрузка данных для фильтров инициализируется на странице списка, чтобы при работе SSR данные подготовились еще на сервере;
	2. фильтры открываются как вариант через модальное окно (см. список активностей `src/modules/chem-zanyatsya`);
	3. загрузка первичных данных для фильтров может открываться как на сервере, так и в окне списка (вероятней даже в окне списка, если содержимое фильтра при загрузке страницы не отображается);
	4. см. файл с [[Nuxt.js/ПОЛЕЗНЫЕ ДАННЫЕ|полезными данными по Nuxt.js]], п. 5 (загрузка данных при SSR);
3. ==Извлечение данных из базы==:
	1. любые запросы на получение информации, сохраняемой в хранилище, при SSR не должны выполняться в хранилище, т.к. оно (см. п.2) существует только на клиенте. Другими словами - **fetch-запросы осуществляем из любых модулей, кроме объектов хранилища**, которое инициализируется на клиенте, иначе получим предупреждение браузера в духе "*набор данных SSR отличается от набора данных в клиенте*"
	2. любые запросы на получение *статической* информации (которая не меняется или меняется очень редко) должны производиться при первом обращении к требуемым данным, которые должны **сохраняться в хранилище, а затем браться только оттуда**;
4. ==Тематические посты== (с разбивкой по темам: article, news, event, offer):
	1. модуль **`ThemePosts`** в директории `src/components/common/ThemePosts.vue`;
	2. расположены в компоненте `src/components/common/ThemePosts`;
	3. получают данные по API-запросу `api/v1/posts/{type}`, где **`type`** - это тип поста:
		* article - статья;
		* event - мероприятие;
		* news - новость;
		* offer - акция;
	4. параметры:
		* **`linked_type`** - тип связанной записи из вариантов `[partners, activities, restaurants, hotels, services, tours]`. Привязка поста к определенному `linked_type` производится в админке путем добавления объектов - партнеров, отелей, кафе и т.д. - к созданной записи:

		  что означает, что к данная новость связана с указанным отелем; 
	5. извлечение данных по запросу с указанием параметра `hotels` теперь вернет все посты, которые связаны с отелями;
5. **ВАЖНАЯ ЗАМЕТКА**: 
   Если пользуемся тестовой и боевой админками, то ==часовой пояс пользователя и там, и там должен совпадать==! Иначе форматирование одних и тех же записей с одинаковым временем, которое заносилось в базу, будет выводить в итоге совершенно разный результат. Данные сохраняются в БД в UTC-формате, а затем в [[Vue.js/ПОЛЕЗНЫЕ ДАННЫЕ|dayjs]] трансформируются в нужный формат.
