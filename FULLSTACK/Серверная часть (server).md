
Серверная часть подразумевает создание proxy-прослойки для формирования api-запросов к бэкенду. Особенности:
1. располагается в папке `server/`;
2. может содержать внутри себя:
	1. подпапку `server/api`, внутри которой размещаются *ts-файлы* с контентом GET/POST/и т.д. запросов, возвращающие нужные данные. Адрес апи-запроса будет равен названию файла внутри папки с префиксом: `api/filename`, а запросы к серверу внутри этих файлов уже имеют прямой доступ к api-серверу бэкенда:
		1. в файлы запросов можно добавлять **постфикс**, равный методу запроса, например `server/api/list.get.ts` (get-запрос), `server/api/update.post.ts` (post-запрос), что не позволит выполнять эти запросы без соответствующего указания метода при вызове запроса на клиенте;
	2. подпапку `server/routes`, аналогичную предыдущей, но, однако, позволяющей перейти к результату запроса по адресу *без префикса* `api/`;
	3. подпапку `server/middleware`, в которую можно вкладывать дополнительный функционал;
3. каждый файл должен экспортировать дефолтную функцию с помощью `defineEventHandler`, например:
   
	```ts
	export default defineEventHandler((event) => {
		return {
			data: 'Результат api-запроса',
		};
	})
	```

	* по умолчанию файл допускает построение любого вида запроса - GET/POST/DELETE/PATCH и т.д.;
	* чтобы ограничить тип запроса при обращении к файлу, требуется установить соответствующий постфикс к названию файла, например `api/filename.get.ts` или `routes/filename.post.ts`;
	* в случае обращения к файлу с другим типом запроса будет получена ошибка;

1. **для создания api-запроса требуется выполнить fetch-запрос на прокси-сервер вида**:
   
	```ts
	const response = await $fetch('api/filename')
	```

	* в данном случае при вызове этого запроса идет обращение к прокси-запросу из директории `server/api/...`;
	* из серверной директории выполняется уже запрос на апи-сервер, извлекающий фактические данные;
	* в прокси-запросе можно обработать результат нужным образом и отдать клиенту уже отформатированные данные;
	* ==если требуется при прокси-запросе исключить сохранение извлеченных данных в кэш== (а это происходит при повторе одного и того же запроса в рамках одной сессии), нужно добавить в прокси-запрос уникальный параметр, например, таймстемп:

		```ts
		const result = await $fetch('api/filename', { query: { _: Date.now() } })
		```

	* чтобы каждый раз не дополнять прокси-запрос одним и тем же query-параметром, можно создать на клиенте функцию-обертку над $fetch, внутри которой будет производиться автоматическая привязка уникального query-параметра к запросу.
