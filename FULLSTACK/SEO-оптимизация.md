## Редиректы для SEO-оптимизации
Использование **серверных миддлваров** (`/server/middleware`)^[см. проект "Завидово", миддлвар `/server/middleware/redirects.ts`]. Срабатывает *только один раз при серверном рендеринге*. Идеально для:
1. редиректов (301) для исключения индексации первичного варианта URL роботами;
2. добавления/удаления последних слэшей из URL (в случае, если версия Nuxt не поддерживает опцию в конфигурации `router: { trailingSlash: true }`);

Использование **клиентских миддлваров** (`/middleware`)^[см. проект "Завидово", миддлвар `/middleware/02.trailing-slash.global.ts` - для добавления последних слэшей в адресную строку]. Особенности:
1. Срабатывает для любой клиентской навигации (в рамках уже отрендеренного сайта), когда обращения к серверному миддлвару уже не производится;
2. Оптимально для редактирования query-параметров, например, указания инициализирующего шага визарда при загрузке страницы;
3. Для случаев, когда требуется добавить/удалить trailing slash в URL, подойдет только такой вариант.

# Справочник: Настройка метатега `<meta name="robots">`

Например, можно отключить конкретную страницу от индексации, отслеживания метриками. В проекте Завидово была отключена полностью одна страница (отдельная карта, которая подключалась как фрейм на другие страницы), чтобы на нее невозможно было перейти откуда-нибудь из поисковика.

**Метатег** `<meta name="robots">` управляет поведением поисковых роботов (краулеров) на уровне конкретной HTML-страницы. Он размещается строго внутри секции `<head>`.

## Базовый синтаксис

```html
<meta name="robots" content="директива_1, директива_2" />
```

*Если вместо `name="robots"` указать имя конкретного бота (например, `name="googlebot"` или `name="yandex"`), директивы будут применяться только к нему.*

---

## 1. Основные (базовые) директивы

| Директива | Что означает | Описание и нюансы |
| :--- | :--- | :--- |
| **`index`** | Индексировать страницу | Разрешает поисковикам добавлять страницу в поисковую выдачу. Это поведение по умолчанию, поэтому тег можно не писать. |
| **`noindex`** | Не индексировать | Запрещает показывать страницу в результатах поиска. Робот всё ещё может зайти на страницу, но в индекс она не попадет. |
| **`follow`** | Переходить по ссылкам | Разрешает роботу сканировать ссылки на этой странице и передавать по ним «ссылочный вес» (PageRank). Поведение по умолчанию. |
| **`nofollow`** | Не переходить по ссылкам | Запрещает роботу переходить по ссылкам, размещенным на этой странице. Вес по ссылкам не передается. |
| **`all`** | Без ограничений | Эквивалент комбинации `index, follow`. Действует по умолчанию, если тег отсутствует. |
| **`none`** | Полный запрет | Эквивалент комбинации `noindex, nofollow`. Робот полностью игнорирует страницу и ссылки на ней. |

---

## 2. Расширенные директивы (Управление сниппетами)

Эти директивы помогают точечно настроить, как именно страница будет выглядеть в поисковой выдаче (в сниппетах).

### `noimageindex`
* **Что делает:** Запрещает индексировать изображения на этой странице.
* **Применение:** Картинки со страницы не появятся в поиске по картинкам (Google Картинки / Яндекс.Картинки). При этом сам текст страницы может быть проиндексирован.

### `noarchive`
* **Что делает:** Запрещает поисковикам сохранять копию страницы в кэш.
* **Применение:** В выдаче возле ссылки на ваш сайт исчезнет кнопка «Сохраненная копия». Полезно для страниц с динамическими ценами или личными данными, чтобы пользователи не видели устаревшую информацию.

### `nosnippet`
* **Что делает:** Запрещает показ любого текстового фрагмента или видео-превью в поисковой выдаче.
* **Применение:** Поисковик покажет в выдаче только заголовок (Title) и ссылку. Мета-описание (Description) и текст со страницы отображаться не будут.

### `max-snippet:[число]`
* **Что делает:** Задает максимальное количество символов для текстового сниппета.
* **Применение:** 
  * `max-snippet:0` — эквивалентно `nosnippet`.
  * `max-snippet:-1` — длина сниппета не ограничена (по умолчанию).
  * `max-snippet:50` — робот возьмет максимум 50 символов для описания в выдаче.

### `max-image-preview:[размер]`
* **Что делает:** Управляет размером превью-изображений в выдаче (например, в Google Discover).
* **Доступные значения:**
  * `max-image-preview:none` — не показывать картинку-превью.
  * `max-image-preview:standard` — показывать стандартное маленькое изображение.
  * `max-image-preview:large` — разрешить показ большой картинки во всю ширину.

### `max-video-preview:[число]`
* **Что делает:** Задает максимальную длительность (в секундах) для анимированного превью видеороликов в выдаче.
* **Применение:** `max-video-preview:-1` означает отсутствие ограничений, а `0` запретит показ анимированного превью (останется статичный кадр).

### `unavailable_after:[дата/время]`
* **Что делает:** Указывает точное время, после которого страницу нужно удалить из поисковой выдачи.
* **Формат:** Время задается в формате RFC 850 (например, `unavailable_after: Monday, 31-Aug-2026 15:00:00 UTC`). После этой даты роботы начнут воспринимать страницу как `noindex`. Полезно для временных акций или страниц мероприятий.

### `notranslate`
* **Что делает:** Запрещает поисковикам предлагать пользователю автоматический перевод этой страницы в выдаче.

## 3. Частые комбинации и примеры использования

* **Страницы авторизации, корзины, личного кабинета:**
  ```html
  <meta name="robots" content="noindex, nofollow" />
  ```
* **Страницы пагинации (каталоги, блоги), где нужно закрыть дубли текста, но дать роботу пройти по ссылкам на товары/статьи:**
  ```html
  <meta name="robots" content="noindex, follow" />
  ```
* **Защита конфиденциального контента от попадания в кэш при сохранении видимости сайта:**
  ```html
  <meta name="robots" content="index, follow, noarchive" />
  ```

## ⚠️ Важное правило взаимодействия с robots.txt

Если страница заблокирована в файле **`robots.txt`** с помощью директивы `Disallow`, поисковый робот **никогда не зайдет на нее и не увидит ваш метатег `<meta name="robots" content="noindex">`**. 

**Правильный алгоритм для полного удаления страницы из индекса:**
1. Страница должна быть **открыта** для сканирования в `robots.txt`.
2. На самой странице должен стоять метатег `<meta name="robots" content="noindex">`.
3. Только после того, как робот зайдет на страницу, увидит тег и удалит её из выдачи, её можно закрывать в `robots.txt` (при необходимости).
