#logging #logs

Этапы:
1. установка пакетов:
	1. `dayjs` (опционально, только для удобного создания дат);
	2. `winston` - подключение пакета логирования (одного из наиболее популярных);
	3. `zod` (опционально, для строгого типизирования данных, с вылетом ошибок).
2. создание серверного функционала логирования (в папке `/server`) - поскольку операции логирования должны проводиться на сервере, а файлы сохраняться там же в корневой директории:
	1. файл `/api/log-error.post.ts` - требуется для логирования записей на клиенте путем обращения к серверу и обновления там файла лога:
	   
		```ts
		import logger from "~/server/utils/logger";
		import { z } from "zod";
		
		const logSchema = z.object({
		    action: z.string(),
		    message: z.string(),
		    level: z.enum(["info", "warn", "error"]).default("error"),
		    meta: z.record(z.any()).optional(),
		});
		
		export default defineEventHandler(async (event) => {
		    try {
		        const body = await readBody(event);
		        const parsed = logSchema.safeParse(body);
		
		        if (!parsed.success) {
		            // ошибки событий, не содержащих body - такие, вероятно, лучше не записывать в логи
		            const clientIp = getRequestIP(event) || "unknown";
		            const now = new Date().toISOString();
		            console.error(`[${now}] ❌ERROR: [LOGGING ERROR] Невалидное тело запроса от клиента ${clientIp}`);
		            return;
		            // throw createError({ message: `Невалидное тело запроса от клиента ${getRequestIP(event) || "unknown"}` });
		        }
		        
		        const { action, message, level, meta } = parsed.data;
		        const logMessage = `[CLIENT] Action: ${action} | Message: ${message} | Meta: ${ JSON.stringify(meta || {}) ?? "" }`;
		
		        logger[level](logMessage);
		
		        return { success: true };
		    } catch (err: any) {
		        logger.error(`[LOGGING ERROR] ${event}`);
		        logger.error(`[LOGGING ERROR] ${err.message}`);
		        return sendError(event, createError({ statusCode: 400, statusMessage: "Invalid log payload" }));
		    }
		});
		```
	   
	2. файл `/utils/logger.ts` - непосредственно сам инструмент логирования с возможностью записи в файл лога:
	   
		```ts
		import winston from "winston"
		import dayjs from "dayjs"
		import fs from "fs"
		import path from "path"
		
		const logDir = path.resolve(process.cwd(), "logs");
		
		// Создание папки, если не существует
		if (!fs.existsSync(logDir)) fs.mkdirSync(logDir);
		
		const logLevelIcon: Record<string, any> = {
		    error: "❌",
		    warn: "⚠️",
		    info: "ℹ️",
		};
		
		const logger = winston.createLogger({
		    level: "info",
		    format: winston.format.combine(
		        winston.format.timestamp({ format: "YYYY-MM-DD HH:mm:ss" }),
		        winston.format.printf(
		            ({ timestamp, level, message }) =>
		                `[${timestamp}] ${logLevelIcon[level] ?? ""}${level.toUpperCase()}: ${message}`
		        )
		    ),
		    transports: [
		        new winston.transports.File({
		            filename: path.join(logDir, `${dayjs().format("YYYY-MM-DD")}.log`),
		            level: "info",
		        }),
		    ],
		});
		
		export default logger;
		```
	   
	3. файл `/composables/useLogger.ts` - клиентский композабл, упрощающий вызов серверного апи-запроса для записи лога:
	   
		```ts
		export const useLogger = () => {
		    const logClientError = async (
		        action: string,
		        message: string,
		        level: "info" | "warn" | "error" = "error",
		        meta: Record<string, any> = {}
		    ) => {
		        try {
		            await $fetch("/api/log-error", {
		                method: "POST",
		                body: { action, message, level, meta },
		            });
		        } catch (e) {
		            console.error("Ошибка при отправке лога:", e);
		        }
		    };
		
		    return { logClientError };
		};
		```
	   
	4. запись лога в любом месте кода: 
	   ```ts
		useLogger().logClientError(
			'Ошибка', 
			'Описание ошибки', 
			'error', // error / warn / info
			{ test: "Тестовая мета-информация" }
		);
		```

2. **Ошибка загрузки пользовательских данных** - загрузка данных для 2-й (одноименной) вкладки в личном кабинете пользователя. Та же ошибка, что и №1, т.к. токен некорректный, а на клиенте юзер еще не разлогинен (*данные в хранилище не почищены, поэтому они есть в мета-данных лога*);
3. **Ошибка авторизации** - попытка авторизации в случае, если не передан или некорректен пароль.
