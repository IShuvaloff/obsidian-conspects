# План обучения HelpMeIn: Laravel / Fullstack

> [!summary]
> Это долгосрочный roadmap pet-проекта HelpMeIn, а не учебник и не перечень всех технологий. Он помогает сверить текущую точку, следующий практический шаг и сознательно отложенные ветки.

## Маршрут в одной строке

```text
Карта проекта → Laravel/PHP → PostgreSQL → domain + Eloquent → Inertia/Vue + TS
→ forms/auth/authorization → vertical slice → reliability/integrations
→ testing → production → deployment → CI → portfolio review
```

Основной стек: Laravel 13, Inertia.js, Vue 3, TypeScript и PostgreSQL. Node/Nest не открываются как параллельный backend-трек.

## Статусы

- ✅ пройдено
- 🟡 изучается / частично пройдено
- ⭕ впереди
- ⏸ сознательно отложено

## Фазы маршрута

### Фаза 0. Карта существующего HelpMeIn — 🟡

**Цель:** понять текущий проект до архитектурных изменений.

**Темы:** общая архитектура Laravel + Inertia + Vue; request/response flow; routes, middleware, controllers, Eloquent models; Inertia pages, props и shared props; текущие authentication infrastructure и Fortify; layouts; shadcn/reka/ui-компоненты; структура БД, migrations и seeders.

**Уже пройдено:** [[0. Общая конструкция]], [[1. Жизненный цикл]], [[2. PHP Base]].

**Переход дальше:** можно объяснить путь `/clients`, найти ключевые файлы проекта и назвать, где находятся auth, frontend pages и DB schema.

### Фаза 1. Laravel application skeleton — 🟡

**Цель:** уверенно читать каркас Laravel-приложения.

**Темы:** `public/index.php`, `bootstrap/app.php`, Application, routing, middleware, controllers, Request / Response, route groups, invokable controllers, configuration, `.env`, lifecycle web / console, [[3. Сервисы и фасады|Service Container / Providers / Facades]]. Эти механизмы закрепляются по реальной необходимости в проекте, а не как абстрактные internals.

**Переход дальше:** новый простой route проходит через middleware в controller, а путь request и Response можно объяснить без «магии».

### Фаза 2. PHP minimum for Laravel — 🟡

**Цель:** закрыть конструкции, необходимые для чтения и написания Laravel-кода, а не изучать PHP целиком.

**Темы:** namespaces, `use`, classes / objects, visibility, inheritance, interfaces, traits, constructors, magic methods, static / instance, type hints, nullable / union types, arrays, closures, arrow functions, callbacks, named arguments; exceptions, enums и attributes — когда встретятся в проекте. Collections изучаются вместе с Laravel.

**Переход дальше:** можно самостоятельно разобрать небольшой controller или middleware, включая imports, type hints, callback и return value.

### Фаза 3. PostgreSQL + migrations — 🟡

**Цель:** перевести HelpMeIn с учебного SQLite на PostgreSQL и сделать БД полноценной частью backend-проекта.

**Уже пройдено:** PostgreSQL установлен и подключён; создана database `help_me_in`; application role `help_me_in_app` используется; Laravel работает через `pgsql`, а `pdo_pgsql` проверен. Вся история migrations успешно выполнена на PostgreSQL: `teacher_student_relationships` создана, реальные constraints и indexes проверены, а уже применённая dates CHECK корректно изменена отдельной новой migration. Подробности среды — в [[4. PostgreSQL и миграции|уроке 4]], а механика migrations — в [[5. Миграции|уроке 5]].

**Остаётся в фазе:** factories, seeders, воспроизводимое пересоздание database и backup/restore basics. Это не мешает следующему учебному шагу: PHP `enum`, затем следующий domain/migration шаг, domain model и Eloquent relationships.

**Отдельный безопасный сценарий:** PostgreSQL на отдельной машине/сервере, LAN-доступ, `listen_addresses`, `pg_hba.conf`, firewall; порт 5432 не открывается в Internet без необходимости.

**Следующий переход:** PHP `enum` → следующий domain/migration шаг → domain model → Eloquent models и relationships. Factories, seeders и backup/restore останутся отдельными незавершёнными частями этой фазы.

### Фаза 4. Domain model HelpMeIn — ⭕

**Цель:** спроектировать реальные сущности продукта до хаотичного наращивания таблиц.

**Use cases:** teacher, student, registration / invitations, управление students учителем, profiles, tasks, task groups/types, questions, answer options, assignment, submission / student answer, review, status, feedback/comments.

**Решения до реализации:** что является общей auth-entity; что относится к teacher/student profile; нужны ли roles; какие связи действительно нужны. `users` не раздувается автоматически.

**Переход дальше:** есть компактная схема сущностей и связей, которая покрывает первый vertical slice.

### Фаза 5. Eloquent + relationships — ⭕

**Цель:** выражать domain model HelpMeIn через Eloquent.

**Темы:** model, fillable, hidden, casts, accessors/mutators при необходимости, `hasOne`, `hasMany`, `belongsTo`, `belongsToMany`, pivot tables, eager loading, N+1, scopes, pagination, query builder, collections, transactions.

**Переход дальше:** relations реализованы на реальных сущностях, запросы не создают очевидный N+1, а списки пагинируются там, где это нужно.

### Фаза 6. Inertia + Vue — ⭕

**Цель:** понимать bridge Laravel backend ↔ Vue frontend.

**Темы:** Inertia page, props, shared props, initial page visit, SPA navigation, forms, validation errors, redirects, flash messages, layouts, `usePage`, server-provided state, server state / client state, partial reloads, preserve state / scroll; Wayfinder — только если он реально используется.

**Граница:** Inertia shared props ≠ Pinia/global frontend store.

**Переход дальше:** новый server use case корректно передаёт props, ошибки и redirect обратно на Vue page без дублирования состояния.

### Фаза 7. TypeScript в Laravel + Inertia + Vue — ⭕

**Цель:** использовать TypeScript на границе backend ↔ frontend, а не как декорацию.

**Темы:** page/shared props, User types, forms, DTO-like frontend contracts, nullable data, discriminated unions, безопасный mapping backend data → frontend, runtime validation boundary, границы гарантий TS.

**Переход дальше:** props и формы имеют полезные типы, а runtime-данные не ошибочно считаются проверенными только TypeScript.

### Фаза 8. Forms + validation — ⭕

**Цель:** построить реальные CRUD и user flows.

**Темы:** Laravel validation, Form Requests, server-side validation, Inertia form handling, frontend errors, old values/state, create/update, nested inputs, domain rules, error UX.

**Практика:** profiles, students, tasks, questions.

**Переход дальше:** один полный create/update flow над реальной сущностью валидируется на сервере и даёт понятную ошибку в UI.

### Фаза 9. Authentication — ⭕

**Цель:** понять и использовать существующую auth infrastructure, не переписывая её без причины.

**Темы:** session-based auth, session cookie, guards, `$request->user()`, Fortify, login, registration, reset password, email verification, remember me, 2FA, passkeys, rate limiting, session security.

**Переход дальше:** текущий Fortify/auth flow прослежен и меняется только под подтверждённый use case.

### Фаза 10. Authorization / roles / policies — ⭕

**Цель:** отделить «кто пользователь» от «что ему разрешено».

**Темы:** authentication vs authorization, roles, admin / teacher / student, Gates, Policies, route protection, controller authorization, ownership, UI visibility vs backend security.

**Критический сценарий:** `/clients` не отдаёт всех users каждому `auth + verified`; teacher видит только своих students, student не получает teacher-level access.

**Переход дальше:** критичные действия защищены на backend, а не только скрыты в UI.

### Фаза 11. Core HelpMeIn features — ⭕

**Цель:** собрать минимальный рабочий vertical slice.

**Порядок:** teacher registration/login → создание и управление student → student login → создание task → questions → открытие task студентом → submission → review → status → feedback.

**Принцип:** сначала завершённая вертикаль, затем усложнение домена, затем styling.

**Переход дальше:** пользовательский сценарий teacher → student → task → answer → review работает end-to-end.

### Фаза 12. Transactions — ⭕

**Цель:** защищать целостность сложных операций.

**Темы:** DB transaction, rollback, атомарность, multi-table writes, assignment + questions, submission + answers, invitations, failure scenarios.

**Переход дальше:** хотя бы один многотабличный use case атомарен и имеет понятный сценарий ошибки.

### Фаза 13. Files / storage — ⭕

**Темы:** user photo, task attachments, public/private storage, validation, naming, cleanup, local/production disks, безопасный доступ к файлам.

**Переход дальше:** прикреплённый файл хранится и выдаётся согласно правам доступа, а ненужные файлы очищаются предсказуемо.

### Фаза 14. Mail + notifications — ⭕

**Темы:** email, invitations, verification, Laravel Notifications, channels, mail templates, retries.

**Переход дальше:** один реальный сценарий уведомления проверен локально и подготовлен к production delivery.

### Фаза 15. Telegram integration — ⭕

**Цель:** подключить Telegram как реальную внешнюю интеграцию HelpMeIn.

**Темы:** bot, webhook, secret/token, external API, retry, queue, validation, security; confirmation messages, task events, invitations/status updates.

**Переход дальше:** интеграция покрывает конкретный продуктовый сценарий и безопасно обрабатывает ошибки внешнего API.

### Фаза 16. Queues / Jobs / Events / Listeners — ⭕

**Темы:** queue, job, worker, retry, failed jobs, events, listeners, notifications, email, Telegram, long-running work вне HTTP request.

**Переход дальше:** реальная тяжёлая или внешняя операция вынесена в queue и её сбои наблюдаемы.

### Фаза 17. API / Sanctum — ⏸

**Правило:** не строить REST API только ради портфолио. Фаза начинается при реальной внешней границе: Telegram, mobile client, отдельный client или integration.

**Темы:** API routes, Sanctum, token auth, API Resources, validation, authorization, rate limiting, CORS. Отдельно различать session auth Inertia app и API token auth.

**Переход дальше:** внешний клиент имеет обоснованную и защищённую API-границу.

### Фаза 18. Security review — ⭕

**Цель:** провести отдельный review сквозной безопасности.

**Темы:** CSRF, XSS, SQL injection, mass assignment, authorization, password hashing, session fixation, cookies, HttpOnly, Secure, SameSite, rate limits, file upload security, secrets, `.env`, logs без secrets.

**Переход дальше:** критические threat points проверены применительно к реальным flows HelpMeIn.

### Фаза 19. Testing — ⭕

**Старт:** после устойчивого backend vertical slice, но не в самом конце проекта.

**Темы:** Pest, unit/feature/database tests, auth, authorization, factories, fakes, queues, notifications, isolation; Vitest, Vue Test Utils и component tests; Playwright E2E для критичных flows.

**Переход дальше:** critical path защищён backend feature tests, а наиболее ценный пользовательский flow имеет E2E-проверку.

### Фаза 20. Performance — ⭕

**Темы:** query count, N+1, eager loading, indexes, pagination, caching, queueing, DB bottlenecks, Inertia payload size; PostgreSQL `EXPLAIN` и query optimization.

**Переход дальше:** измерен и устранён хотя бы один реальный bottleneck, а не применены «оптимизации» вслепую.

### Фаза 21. Production configuration — ⭕

**Темы:** `.env`, config/route cache по необходимости, app key, debug off, logs, permissions, storage, queues, cron/scheduler, secrets, production DB.

**Maintenance nuance:** `php artisan down/up`, custom maintenance / 503 page, maintenance при migration/deployment, controlled developer bypass.

**Переход дальше:** есть проверяемый production checklist без секретов в repository.

### Фаза 22. Deployment — ⭕

**Цель:** самостоятельно развернуть HelpMeIn на Timeweb/VPS.

**Среда и темы:** Linux, Nginx, PHP-FPM, Composer, Node/Vite build, PostgreSQL, SSL/TLS, queues, cron, logs; deploy user, permissions, repository, environment, `composer install`, `npm build`, migrations, storage link, workers, scheduler, rollback и backup.

**Переход дальше:** приложение доступно по HTTPS, переживает перезапуск процессов, а rollback и backup понятны и проверяемы.

### Фаза 23. CI — ⭕

**Старт:** после появления тестов и понятного production deploy.

```text
commit / merge → install → lint / typecheck → backend tests → frontend tests
→ build → optional image/artifact → controlled deployment
```

**Переход дальше:** pipeline проверяет изменения до deploy. CI не изучается абстрактно раньше testing/deployment.

### Фаза 24. Payments — ⏸

**Условие старта:** реальная платная модель HelpMeIn.

**Темы:** provider, payment intent/order, callback/webhook, signature verification, idempotency, повторная доставка webhook, transaction, payment status, refunds/cancel, logging и security.

**Переход дальше:** платежи не внедряются «для галочки»; выбранный провайдер покрывает реальную модель продукта.

### Фаза 25. Production architecture review — ⭕

**Цель:** проверить HelpMeIn как portfolio/fullstack system.

**Review:** domain model, boundaries, auth, authorization, validation, transactions, queues, integrations, tests, security, DB design, indexes, logs, backup, deployment, CI, maintainability.

**Переход дальше:** есть список осознанных trade-offs и приоритетный backlog улучшений.

### Фаза 26. Interview review — ⭕

**Цель:** уметь объяснить, почему HelpMeIn устроен именно так.

**Подготовить:** architecture explanation, request lifecycle, auth flow, DB model, Eloquent relations, transactions, queues, testing strategy, deployment, CI, trade-offs, ошибки и refactoring decisions.

**Переход дальше:** проект можно не только показать, но и уверенно разобрать в разговоре с коллегой или на интервью.

## Правила движения по плану

1. Не начинать новую крупную фазу, пока предыдущая не понята на уровне, достаточном для практики.
2. Не требовать идеального знания перед движением дальше.
3. Возвращаться к теме, когда она становится практически нужна.
4. Не изучать framework internals ради internals.
5. Использовать HelpMeIn как основной источник примеров.
6. Сначала functionality → затем reliability → затем styling/polish.
7. Styling и UI-polish сознательно отложены ближе к концу.
8. PostgreSQL должен стать основной БД проекта.
9. Testing — обязательный этап, а не optional appendix.
10. CI изучается после появления тестов.
11. Production delivery изучается на реальном deployment HelpMeIn.
12. Node/Nest не открывать как второй backend-трек до завершения основного Laravel-маршрута.
