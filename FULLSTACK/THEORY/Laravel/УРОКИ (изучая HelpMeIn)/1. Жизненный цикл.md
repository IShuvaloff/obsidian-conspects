# Жизненный цикл HTTP-запроса Laravel

## Зачем это нужно

Понимание HTTP lifecycle нужно, чтобы перестать воспринимать Laravel как набор магических методов и видеть реальный путь запроса: вход в приложение → bootstrap → Request → routing → middleware → controller → Response.

## Короткая карта

```text
Browser → web server → public/index.php → bootstrap/app.php → Laravel Application
→ Request → middleware → router → route middleware → controller → Response
→ middleware unwind → web server → Browser
```

Это подробное продолжение [[0. Общая конструкция|общей конструкции HelpMeIn]]. PHP-синтаксис и базовые механизмы кода вынесены в [[2. PHP Base]].

## Что запускают `public/index.php` и `bootstrap/app.php`

`public/index.php` — front controller, то есть единая HTTP entry point. Почти все web-запросы попадают в него через настройку web server. Файл намеренно маленький: он только запускает framework.

- `LARAVEL_START` фиксирует время старта для каждого HTTP request.
- `require vendor/autoload.php` подключает Composer autoloader.
- `bootstrap/app.php` возвращает объект Laravel `Application`.
- `Request::capture()` создаёт Laravel `Request` из текущего HTTP environment.
- `$app->handleRequest(...)` запускает обработку запроса.

В `bootstrap/app.php` конфигурируется `Application`:

- `withRouting(...)` подключает web routes, console routes и health endpoint;
- `withMiddleware(...)` настраивает middleware pipeline;
- `withExceptions(...)` настраивает обработку исключений;
- `create()` создаёт объект `Application`.

В обычной PHP/FPM-модели `Application` создаётся заново для каждого HTTP request. `require_once` означает лишь, что один и тот же файл не выполняется повторно в рамках **одного** PHP execution.

### Composer и PSR-4

```php
use App\Models\User;
```

`use` разрешает короткое имя класса. А Composer autoload вместе с PSR-4 находит его физический файл: `App\Models\User` → `app/Models/User.php`.

### PHP-FPM

PHP-FPM — менеджер пула PHP worker-процессов, через который Nginx обычно передаёт PHP-запросы в production. Worker может жить долго, но стандартный Laravel request lifecycle начинается заново для каждого HTTP request.

### **Onion**-стиль жизненного цикла:

```
Middleware A {
    Middleware B {
        auth {
            verified {
                Controller
            }
        }
    }
}
```

### Поведение миддлвара

Именно из-за двусторонней направленности мы можем настроить в middleware обработку `request` до controller и `response` после controller:

```php
public function handle(Request $request, Closure $next): Response
{
    // BEFORE controller
    $response = $next($request);

    // AFTER controller
    return $response;
}
```

### Паттерны поведения миддлваров

```php
// 1. Пропустить request дальше
return $next($request);

// 2. Остановить pipeline
return redirect('/login');
// или
return response('Forbidden', 403);

// 3. Изменить request и передать дальше
$request->merge(['foo' => 'bar']);
return $next($request);

// 4. Получить response после controller,
// изменить его и вернуть дальше
$response = $next($request);
$response->headers->set('X-Test', '123');

return $response;
```

> Middleware может работать **до controller и после controller**, потому что оборачивает весь request/response cycle.

### Middleware group

Middleware group позволяет применить один набор middleware сразу к нескольким routes.

```php
Route::middleware(['auth', 'verified'])->group(function () {
    Route::get('clients', ...);
    Route::get('tasks', ...);
});
```

`Route::get('clients', ...)` и `Route::get('/clients', ...)` для обычного Laravel routing практически эквивалентны: ведущий `/` нормализуется. В проекте лучше придерживаться одного стиля.

### Invokable controller

```php
Route::get('clients', ClientController::class);
```

Это работает, потому что controller содержит `public function __invoke()`. `__invoke()` — magic method PHP, позволяющий объекту быть callable.

## Команды разработчика, DevOps, deployment script

### `php artisan down`

Включает режим технического обслуживания приложения.

### `php artisan up` 

Возвращает приложение в обычный режим.

`php artisan down` и `php artisan up` — встроенные Artisan-команды Laravel. `routes/console.php` предназначен для пользовательских console routes/commands, но не является источником всех Artisan-команд.

## Краткое резюме

| Этап | Ответственность |
|---|---|
| `public/index.php` | Единая точка входа и запуск Laravel. |
| `bootstrap/app.php` | Создание и конфигурация `Application`. |
| Middleware | Оборачивают request/response; могут пропустить, остановить или изменить их. |
| Router | Находит обработчик по HTTP method и URL. |
| Controller | Выполняется один раз и возвращает Response. |
| Middleware unwind | Возвращает Response наружу через уже пройденные middleware. |

Формулировка для повторения: **Controller не выполняется повторно на обратном пути: Response разворачивается только через middleware pipeline.**

## Для проверки знаний

### Термины

- Front controller, bootstrap, Laravel Application, Composer autoload, PSR-4.
- HTTP Request, HTTP Response, middleware pipeline, route middleware.
- Invokable controller, middleware group, maintenance mode.

### Что нужно уметь объяснить

- Полный путь `GET /clients`: browser → web server → `public/index.php` → `bootstrap/app.php` → middleware/router/controller → Response.
- Почему controller формирует Response один раз, а обратный путь проходит только через уже вызванные middleware.
- Различие между `use App\Models\User` и Composer autoload + PSR-4, которые находят файл класса.
- Почему в обычной PHP/FPM-модели Laravel Application создаётся заново на каждый HTTP request, хотя PHP worker может жить долго.

### Типичные ошибки

- Рисовать Response как повторный проход через controller.
- Считать `require_once` гарантией, что Laravel Application переживает несколько HTTP requests.
- Считать `routes/console.php` источником всех Artisan-команд или maintenance mode «режимом разработки».

### Мини-практика

- Предскажи результат: middleware получает Response через `$response = $next($request)`, добавляет заголовок `X-Test`, затем возвращает `$response`. В какой момент header попадёт в browser и будет ли controller вызван повторно?
- МикроТЗ: для routes `clients` и `tasks` предложи middleware group с `auth` и `verified`. Критерий: оба routes защищены одним набором middleware, а controller не содержит эту проверку.
