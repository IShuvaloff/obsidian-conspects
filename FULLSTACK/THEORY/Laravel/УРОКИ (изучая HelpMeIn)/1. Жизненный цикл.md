
## Список PHP терминов

|Конструкция|Что означает|Пример HelpMeIn|
|---|---|---|
|`namespace`|Пространство имён класса|`App\Http\Controllers`|
|`use`|Импорт имени класса|`use Illuminate\Http\Request`|
|`require`|Подключить PHP-файл|Composer autoloader|
|`__DIR__`|Каталог текущего файла|пути в `bootstrap/app.php`|
|`dirname()`|Родительский каталог|определение `basePath`|
|`Closure`|Функция как объект/callback|middleware|
|`::`|Обращение к class/static API|`Request::capture()`|
|`->`|Обращение к объекту|`$request->user()`|
|`__invoke()`|Делает объект callable|`ClientController`|
|type hint|Требуемый тип параметра|`Request $request`|
|return type|Тип результата|`: Response`, `: void`|

## Список Laravel терминов

|Термин|Значение|
|---|---|
|Front Controller|Единая HTTP entry point — `public/index.php`|
|Bootstrap|Начальная настройка/запуск приложения|
|Application|Главный объект Laravel application|
|Autoload|Автоматическая загрузка PHP-классов|
|PSR-4|Правило namespace → directory|
|HTTP Request|Представление входящего HTTP-запроса|
|HTTP Response|Ответ сервера|
|Router|Поиск action по HTTP method + URL|
|Middleware|Слой вокруг обработки request/response|
|Middleware pipeline|Последовательность middleware|
|Route middleware|Middleware конкретного route|
|Invokable controller|Controller с `__invoke()`|
|Service Provider|Регистрация/конфигурация сервисов приложения|
|Health endpoint|Endpoint проверки работоспособности|

## Назначение файлов

```
public/index.php
→ вход

bootstrap/app.php
→ конфигурация Laravel

Request::capture()
→ создание Laravel Request

routes/web.php
→ поиск route

middleware
→ pipeline

controller
→ обработка use case

Response
→ обратный путь (поэтапно: контроллер, миддлвары и т.д.)
```

## Жизненный цикл /clients

```
--------------------------------------------------------------
1. REQUEST:
--------------------------------------------------------------
		↓
2. Browser
   GET /clients
		↓
3. Web server
   document root = /public
		↓
4. public/index.php
        ├── maintenance check
        ├── Composer autoload
		↓
5. bootstrap/app.php
        ├── Application configuration
        ├── routes/web.php
        ├── web middleware
        ├── exception config
        ├── ФОРМИРОВАНИЕ И ВОЗВРАТ LARAVEL-APPLICATION
        ↓
6. Request::capture()
		↓
7. Illuminate\Http\Request
		↓
8. Laravel HTTP pipeline
		↓
9. Middleware (Global Web Stack):
	    ├── Global web middleware A
	    ├── Global web middleware B
		↓
10. Router
   GET /clients matched
		↓
11. Middleware Route:
        ├── auth
        ├── verified
		↓
12. ClientController::__invoke()
		↓
13. User::all()
		↓
14. Database
		↓
15. Eloquent Collection<User>
		↓
16. inertia('Clients', ['users' => ...])
	    ↓
--------------------------------------------------------------
16. RESPONSE:
--------------------------------------------------------------
		↓
17. middleware обратным путём (только миддлвары, без контроллеров!)
		↓
18. Browser
		↓
19. Inertia + Vue
		↓
20. Clients.vue
```

> Laravel Application в стандартной PHP-модели bootstraps (создает $app) заново для каждого HTTP request.

### **Onion**-стиль жизненного цикла:

```
    Middleware B {

            verified {
                Controller
            }
        }
    }
}
```

### Поведение миддлвара

Именно из-за двусторонней направленности мы имеем возможность настроить в контроллере как обработку `request`, так и обработку `response`:

```php
public function handle(Request $request, Closure $next): Response
{
    // BEFORE controller
    $response = $next($request);

    // AFTER controller
    return $response;
}
```

### Паттерны поведения миддлваров

```php
// 1. Пропустить request дальше
return $next($request);

// 2. Остановить pipeline
return redirect('/login');
// или
return response('Forbidden', 403);

// 3. Изменить request и передать дальше
$request->merge(['foo' => 'bar']);
return $next($request);

// 4. Получить response после controller,
// изменить его и вернуть дальше
$response = $next($request);
$response->headers->set('X-Test', '123');

return $response;
```

> Middleware может работать **до controller и после controller**, потому что оборачивает весь request/response cycle.

## Команды разработчика, DevOps, deployment script

### `php artisan down`

Переводит программу в maintenance-режим (режим разработки, обслуживания). Сайт выдает 503, Service unavailable. 

### `php artisan up` 

Запускает программу, выводит из maintenance-режима обратно.
