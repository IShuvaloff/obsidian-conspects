# HelpMeIn: общая конструкция

## Зачем нужен этот урок

Этот урок нужен, чтобы увидеть HelpMeIn как единую систему и понимать, как Laravel, Inertia, Vue, Eloquent и session-based authentication связаны между собой до изучения деталей каждого слоя.

## Короткая карта

`Browser → Laravel route → middleware → controller → Eloquent / DB → Inertia props → Vue page → DOM`.

Подробный путь HTTP-запроса раскрыт в [[1. Жизненный цикл]], а PHP-конструкции, встречающиеся в коде Laravel, — в [[2. PHP Base]].

## Список терминов

|Термин|Коротко|В HelpMeIn|
|---|---|---|
|Route|Соответствие URL обработчику|`/clients`|
|Middleware|Слой вокруг request/response cycle: работает до и после controller либо может остановить дальнейшее выполнение|`auth`, `verified`|
|Controller|Обработчик HTTP use case|`ClientController`|
|Model|PHP/Eloquent представление сущности БД|`User`|
|Eloquent|ORM Laravel|`User::all()`|
|ORM|Отображение DB ↔ objects|`users` ↔ `User`|
|Migration|Версионированное описание структуры БД|`create_users_table`|
|Inertia|Связка Laravel и frontend framework|Laravel → Vue props|
|Page|Vue-компонент страницы Inertia|`Clients.vue`|
|Props|Данные, переданные компоненту|`users`|
|Shared props|Данные, доступные многим Inertia pages|`auth.user`|
|Fortify|Headless authentication backend|login/register/reset/2FA|
|Layout|Общая оболочка страниц|`AppLayout`|
|Cast|Преобразование DB value → PHP type|`is_admin → boolean`|
|Fillable|Разрешённые поля mass assignment|`name`, `email`, `phone`|
|Seeder|Наполнение БД начальными данными|admin|
|Session|Механизм хранения серверного состояния между HTTP requests; authentication — один из сценариев его использования|таблица `sessions`|

## Цепочки событий

1. для **перехода на страницу** со списком пользователей:

```
Browser
 │
 │ GET /clients
 ↓
Laravel
 │
 ├── routes/web.php
 │
 ├── middleware
 │    ├── auth
 │    └── verified
 |
 ↓
ClientController::__invoke()
 |
 | User::all()
 ↓
Eloquent
 ↓
Database
 |
 | users
 ↓
Eloquent Collection<User>
 ↓
inertia('Clients', ['users' => $users])
 ↓
Inertia response
 ↓
resources/js/pages/Clients.vue
 |
 | props.users
 ↓
Vue components
 ↓
Browser DOM
```

> При запросе `/clients` Laravel router находит маршрут и пропускает запрос через `auth` и `verified` middleware. Затем вызывается `ClientController`. Контроллер через Eloquent выполняет `User::all()`, что примерно соответствует `SELECT * FROM users`, и получает коллекцию моделей `User`. Атрибуты моделей могут преобразовываться согласно `casts()`. Затем controller возвращает Inertia response для страницы `Clients`, передавая коллекцию как `users` props. Inertia доставляет название страницы и props frontend-приложению, после чего Vue рендерит `Clients.vue`.

> Эта схема показывает архитектурный поток данных. Подробное различие initial page load и Inertia SPA navigation будет изучено отдельно.
   
2. для процесса **авторизации** пользователя:

```
Browser
 ↓
session cookie
 ↓
Laravel web middleware
 ↓
session
 ↓
Auth / guard
 ↓
User из database
 ↓
$request->user()
 ↓
HandleInertiaRequests::share()
 ↓
auth.user
 ↓
Inertia Page props
 ↓
usePage().props.auth.user
 ↓
Vue
```
   
3. для **получения фотографии авторизованного пользователя**:

```
users.photo
 ↓
Eloquent User
 ↓
$request->user()
 ↓
HandleInertiaRequests::share()
 ↓
auth.user
 ↓
Inertia page props
 ↓
usePage().props.auth.user
 ↓
AppHeader.vue
 ↓
auth.user.photo
```

## Краткое резюме

| Вопрос | Короткий ответ |
|---|---|
| Кто связывает URL и обработчик? | Laravel route и router. |
| Где принимается решение «пустить ли дальше»? | В middleware. |
| Кто реализует HTTP use case? | Controller. |
| Кто читает модели из БД? | Eloquent. |
| Как данные доходят до Vue page? | Laravel возвращает Inertia response с props. |

Формулировка для повторения: **HelpMeIn — Laravel-приложение, где controller получает данные через Eloquent и возвращает их Inertia, а Vue рендерит page из переданных props.**

## Для проверки знаний

### Термины

- Route, middleware, controller.
- Eloquent, model, Inertia page, props и shared props.
- Session, auth / guard, Fortify.

### Что нужно уметь объяснить

- Как `GET /clients` проходит от browser до `Clients.vue`, и какую ответственность несёт каждый слой.
- Почему `auth.user` может быть доступен нескольким Inertia pages, а `users` — props конкретной страницы.
- Как session, auth / guard и `$request->user()` связаны между собой, не сводя session только к авторизации.

### Типичные ошибки

- Считать middleware исключительно проверкой request **до** controller: он может также изменить Response или остановить pipeline.
- Считать `User::all()` обычным PHP array либо считать Inertia глобальным frontend store.
- Путать механизм session с самой authentication: authentication лишь использует session в одном из сценариев.

### Мини-практика

- Для будущего `GET /tasks` назови путь данных от route до Vue page и укажи, на каком шаге проверяются `auth` и `verified`.
- МикроТЗ: спроектируй props для страницы задач так, чтобы список `tasks` был props страницы, а текущий пользователь оставался в `auth.user`. Объясни, почему эти данные не должны поменяться местами.
