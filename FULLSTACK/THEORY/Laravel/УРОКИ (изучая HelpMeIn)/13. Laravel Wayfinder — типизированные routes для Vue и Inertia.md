# Laravel Wayfinder: типизированные routes для Vue и Inertia

#laravel #wayfinder #inertia #typescript #routing

> [!summary]
> Wayfinder читает Laravel routes/controllers и генерирует импортируемые TypeScript helpers. Они возвращают не просто строку, а описание `{ url, method }`; поэтому Vue/Inertia код не дублирует вручную URI и HTTP method. В HelpMeIn уже используются сгенерированные `@/actions/...` и `@/routes/...`.

## Зачем это нужно

Без route helper frontend легко расходится с backend:

```ts
router.post('/student-invitation', data); // typo, неверный URI или method
```

Wayfinder превращает известное Laravel route definition в typed TS function:

```text
routes/web.php + controller signatures
↓ generation
resources/js/actions + resources/js/routes
↓
Vue / Inertia imports
```

В проекте установлена beta `laravel/wayfinder` 0.1.x, поэтому generated API следует сверять с установленной версией. Основной reference — [Wayfinder repository](https://github.com/laravel/wayfinder) и локальные generated files.

## Что возвращает helper

Для action `StudentInvitationController::store` Wayfinder сгенерировал:

```ts
import { store } from '@/actions/App/Http/Controllers/StudentInvitationController';

store();
// { url: '/student-invitations', method: 'post' }

store.url();
// '/student-invitations'
```

```text
store()
→ RouteDefinition: URL + default HTTP method

store.url()
→ только URL string
```

Это ключевое различие. Inertia `<Form>` может принять route definition; `useHttp` или API, ожидающий URL string, получает `store.url()`. Не нужно преобразовывать route object в строку «на глаз».

## Actions и named routes

Wayfinder генерирует два удобных входа:

| Импорт | Когда выбрать |
|---|---|
| `@/actions/App/Http/Controllers/...` | Нужен конкретный controller action. |
| `@/routes/...` | Нужен route по логическому `name(...)`. |

Для одного action, на который ведёт несколько URI, controller helper может стать dictionary URI-вариантов: генератор не может угадать intention. В таком случае named route import обычно яснее.

```ts
import { store } from '@/routes/invitations';

router.post(store.url(), { email });
```

У controller/action и named route не появляется новая backend capability: Wayfinder лишь генерирует клиентское описание уже существующего Laravel route. Если `routes/web.php` ещё не содержит invitation accept endpoint, сгенерировать и ссылаться на него нельзя.

## Parameters и query parameters

Route model binding parameter можно передать ID, object с ожидаемым key или Model-like object — точная TS shape генерируется из Laravel route. Например, используемый status endpoint:

```ts
updateActivityStatus.url(relationship.id);
```

Query options передают отдельно от path parameter согласно generated signature:

```ts
store.url({ query: { source: 'clients' } });
```

Нельзя путать query options с body mutation: `router.post(store.url(), { email })` отправляет `email` как request data, а не автоматически как query string. Всегда полезно посмотреть type/definition через IDE Go to Definition: это точнее, чем воспроизводить API по памяти.

## Как generated code появляется и обновляется

```bash
php artisan wayfinder:generate
php artisan wayfinder:generate --with-form
```

В текущем проекте generated files находятся в `resources/js/actions`, `resources/js/routes` и supporting `wayfinder`; `vite.config.ts` уже подключает `@laravel/vite-plugin-wayfinder` с `formVariants: true`. Это output генератора: руками редактировать его не следует, так как следующее generation/build перезапишет изменения. Явная команда остаётся полезной диагностикой, если Vite plugin не запущен или output нужно обновить вне dev/build процесса.

`--with-form` добавляет `.form()` variants для обычных HTML form attributes. Это не требуется для каждого Inertia `router.post`, но полезно для conventional form scenario.

## Inertia, server routes и ссылки в email

Wayfinder работает на TypeScript client boundary. На PHP-стороне Laravel использует обычные `route()` и `url()` helpers:

```php
route('invitations.store');
url('/invitations/accept');
```

Во временном invitation Job используется `url('/invitations/accept')`, потому что финальный accept route ещё не реализован. Это placeholder для учебного email rendering; он не должен превращаться в claim, что acceptance flow уже работает.

Mailable получает `$actionUrl` как URL value. Blade Markdown component `<x-mail::button :url="$actionUrl">` строит presentation; Wayfinder не генерирует «готовый Markdown link» и не нужен внутри email body.

## Когда Wayfinder полезен, а когда нет

Полезен для Vue/Inertia calls, links и forms, где backend route — источник истины. Не заменяет authorization, validation, Route Model Binding или проверку actual route existence. Для внешнего email URL, CLI task или чистого backend code соответствующий Laravel helper может быть проще.

## Краткое резюме

```text
Laravel route/controller
↓
Wayfinder generation
↓
typed TS helper
↓
RouteDefinition { url, method } или .url()
↓
Vue / Inertia
```

## Для проверки знаний

### Термины
- Wayfinder, generated helper, route definition, action import, named route import.

### Что нужно уметь объяснить
- Чем `store()` и `store.url()` различаются.
- Почему generated files не редактируют вручную.
- Почему Wayfinder не создаёт backend route и не заменяет validation/authorization.

### Типичные ошибки
- Хардкодить URI при существующем typed helper.
- Передавать RouteDefinition туда, где нужен `string` URL.
- Создавать frontend ссылку на ещё несуществующий accept route.

### Мини-практика
- Для PATCH relationship выбери `.url(id)` или route definition в зависимости от API `router`/`useHttp` и объясни выбор.
