#middleware 
## Назначение
1. **Проверка аутентификации и авторизации** — например, middleware `auth` проверяет, вошел ли пользователь в систему, и ограничивает доступ к маршрутам.
    
2. **Защита от CSRF-атак** — middleware `VerifyCsrfToken` проверяет CSRF-токены для POST-запросов, обеспечивая безопасность форм.
    
3. **Логирование и мониторинг** — middleware может вести журнал запросов, считать время обработки, записывать статистику.
    
4. **Фильтрация запросов** — можно отклонить запросы с неподходящими параметрами, или сделать редирект на другие маршруты.
    
5. **Ограничение частоты запросов** — middleware `throttle` защищает от DDoS-атак и слишком частых вызовов.
    
6. **Группировка middleware** — позволяет применить набор middleware к группе маршрутов.
    
7. **Переадресация** — middleware может перенаправлять пользователей (например, если не авторизован).
    
8. **Управление сессиями и куки** — обеспечивают шифрование, доступ и добавление cookies.
    
9. **Обработка CORS** — разрешение или запрет cross-origin запросов.
    
10. **Владение доступом по ролям** — пользовательские middleware для проверки ролей.

## Создание
1. место размещения миддлваров - `/app/Http/Middleware/`;
2. создание нового миддлвара - команда `php artisan make:middleware NewMiddleware`;
3. метод для выполнения действий:
	```php
	namespace App\Http\Middleware;
	use Closure;
	use Illuminate\Http\Request;
	use Symfony\Component\HttpFoundation\Response;
	
	class NewMiddleware {
	    public function handle(Request $request, Closure $next): Response {
	        if ($request->input('token') !== 'my-secret-token') {
	            return redirect('/home');
	        }
	        return $next($request);
	    }
	}
	```
4. вызов `$next($request)` позволяет запросу провалиться дальше в фоновом режиме, а дальнейший `return` возвращает результат обработки запроса обратно;
5. исходя из этого имеем **варианты отработки миддлвара**:
	- до отработки запроса (для авторизации):
		```php
	    public function handle(Request $request, Closure $next): Response {
	        // выполнение действий ДО
	        return $next($request);
	    }
		```
	- после отработки запроса (например, для логирования, отправки уведомлений, очистки временных данных и т.д.):
		```php
		public function handle(Request $request, Closure $next): Response {
	        const $response = $next($request);
	        // выполнение действий ПОСЛЕ
	        return $response;
	    }
		```

## Регистрация

#### Глобальная регистрация
В файле `/bootstrap/app.php`:
```php
use App\Http\Middleware\NewMiddleware;

->withMiddleware(function (Middleware $middleware): void {
	 $middleware->append(NewMiddleware::class);
})
```
- метод `append` - добавление миддлвара в конце глобального списка;
- метод `prepend` - добавление миддлвара в начало глобального списка;

#### Подключение к маршрутам
Через вызов метода `middleware` фасада `Route`:
```php
Route::get(...)->middleware(NewMiddleware::class); // подключение одного миддлвара
Route::get(...)->middleware([MewMiddleware::class, AnotherMiddleware::class]) // несколько
Route::middleware([...])->group(...); // для группы рутов
```

#### Исключить миддлвары
Для отдельных рутов в группе через вызов метода `withoutMiddleware`:
```php
Route::middleware([NewMiddleware::class])->group(function () {
	Route::get(...)->withoutMiddleware([NewMiddleware::class])
})

Route::withoutMiddleware([NewMiddleware::class])->group(...); // для группы рутов
```

#### Группировка миддлваров
Чтобы подключать их к рутам сразу группой через вызов методов `appendToGroup` и `prependToGroup`:
```php
->withMiddleware(function (Middleware $middleware): void {
	 $middleware->appendToGroup('group-name', [
		 NewMiddleware::class,
		 AnotherMiddleware::class,
	);
})
```
Сгруппированные миддлвары подключаются к рутам аналогично.

#### Встроенные группы миддлваров
`web` и `api`. Все они автоматически подключаются к рутам из директорий `/routes/web.php` и `/routes/api.php`. Можно пополнять эти группы кастомными миддлварами с использованием все тех же методов:
```php
->withMiddleware(function (Middleware $middleware): void {
	 $middleware->web(append: [NewMiddleware::class]);
	 $middleware->api(prepend: [AnotherMiddleware::class]);
	 $middleware->api(replace: [StartSession::class => CustomSession::class]); // заменить один миддлвар другим
	 $middleware->web(remove: [NewMiddleware::class]); // удалить ненужный миддлвар
})
```
Возможно [ручное управление встроенными группами миддлваров](https://laravel.com/docs/12.x/middleware#manually-managing-laravels-default-middleware-groups);

#### Добавление алиасов
Позволяет подключать миддлвары к рутам более коротким путем, по алиасу:
```php
->withMiddleware(function (Middleware $middleware): void {
	 $middleware->alias(['new' => NewMiddleware::class]);
})

// подключение миддлвара к руту:
Route::get(...)->middleware('new');
```
Пример: алиас `auth`, относится к встроенному миддлвару, работающему с авторизацией.

#### Сортировка миддлваров для отработки в нужном порядке
```php
->withMiddleware(function (Middleware $middleware): void {
	 $middleware->priority([
		 'another' => AnotherMiddleware::class,
		 'new' => NewMiddleware::class,
	]);
})
```
	
## Параметры
Передача параметров в миддлвар необходима для случаев, если, например, требуется авторизация для определенных ролей пользователя. Для передачи роли через параметр нужно: 
1. добавить параметры после параметра `$next` в методе `handle()` миддлвара:
	```php
	class CheckUserRole {
	    public function handle(Request $request, Closure $next, string $role): Response {
	        if (! $request->user()->hasRole($role)) {
	            // Redirect...
	        }
	        return $next($request);
	    }
	}
	```
2. дописать в подключении миддлвара название значения параметра (в нашем случае роли) через двоеточие, разделенные запятыми, если ролей несколько:
	```php
	Route::put('/post/{id}', function (string $id) {
	    // ...
	})->middleware(CheckUserRole::class.':user,manager');
	```
## Прерываемые миддлвары (terminable)
Это долгие и необязательные операции, выполняемые уже после того, как сервер отдаст результат запроса браузеру и без блокировки браузера. Напоминает функционал операций ПОСЛЕ обработки запроса, может включать в себя:
- логирование;
- отправку почтовых уведомлений или сообщений в очередь;
- очистку временных данных;
- файловые операции;
- формирование отчетов, подсчет статистики и пр.

Запускаются автоматически путем вызова метода `terminate()` в миддлваре, содержащем параметры запроса и респонса:
```php
namespace Illuminate\Session\Middleware;
use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class TerminatingMiddleware {
    public function handle(Request $request, Closure $next): Response {
        return $next($request);
    }

    public function terminate(Request $request, Response $response): void{
        // выполнение требуемых действий...
    }
}
```

==Сравнение с обычным миддлваром==:
1. пока в обычном миддлваре мы не выполним `return`, браузер виснет и ждет возврата ответа. Если его не вернуть, браузер не получит никакого ответа и страница не загрузится.
2. когда метод `handle()` возвращает ответ обратно, включается метод `terminate()`, который уже в фоне может выполнять операции, не блокируя браузер.
