[Создание нового приложения Laravel](https://laravel.com/docs/12.x/installation) включает в себя:
1. Установка последней версии PHP (*8.4.12 на момент создания*). Установка:
	- скачать файл с [оф. сайта](https://www.php.net/downloads.php), версия Thread Safe, .zip;
	- создать директорию php в корне диска D или C: D:\php;
	- выложить содержимое архива внутрь этой директории (проверить наличие файла php.exe в контенте - если его нет, значит, архив некорректный!);
	- скопировать файл php.ini-development, переименовать в php.ini и выполнить нужные настройки (разблокировать минимум)^[чтобы проверить, какие зависимости установлены, можно вызвать команду `php -m`]:

		```d
		extension_dir=ext
		memory_limit=512M (для крупных приложений)
		extension=curl
		extension=fileinfo
		extension=gd
		extension=mbstring
		extension=mysqli
		extension=openssl
		extension=zip
		// следующие могут не быть в файле, проверить их наличие в php -m
		extension=json 
		extension=pdo 
		extension=tokenizer 
		extension=xml
		// для подключения к базам данных (выбрать требуемые)
		extension=pdo_mysql
		extension=pdo_sqlite
		extension=pgsql
		```

	- прописать в системных переменных (глобальных) PATH - директорию D:\php (внутри которой находится файл php.exe);
	- если команда `where php` выдает несколько мест с файлами php.exe, значит, в системных переменных находятся несколько директорий. Нужно убрать лишние;
2. Установка последней версии **Composer** (т.к. ее обновления синхронизируются с обновлениями PHP) (*2.8.11 на момент создания*). Установка:
	- скачать файл с [оф. сайта](https://getcomposer.org/download/) Composer-Setup.exe;
	- установить^[либо обновить до последней версии командой `composer self-update`];
	- установить последнюю версию **Laravel Installer** командой `composer global require laravel/installer --update-with-dependencies`^[чтобы впоследствии убедиться, что установка была глобальная, вызвать `composer global show laravel/installer`. Если не показывается версия, попробовать переустановить еще раз];
	- проверить установленные версии можно командами `composer -v` и `laravel -v` (если последний выдает ошибку, проблема в PATH);
	- проверить пути установки laravel в системных переменных и поправить при необходимости: нужно, чтобы были указаны директории с файлами laravel и laravel.bat^[находятся в папке C:\Users\iashu\AppData\Roaming\Composer\vendor\bin];
3. Обновление Node.js (*20.19.5 на момент создания*):
	- скачать файл с [оф. сайта](https://nodejs.org/en/download). Требуемая версия для установки npm-зависимостей проекта (с версиями инструментов выше) минимум 20.5, выбирается на странице. Лучше всего скачать *.msi-версию для Windows* и переустановить версию в текущую папку C:\Program Files\nodejs^[важно учесть, не затрется ли имеющаяся установленная версия ноды (например, 20-я) в случае установки 22-й таким способом. Должна **остаться возможность переключения версий** с помощью `nvm use ...`!];
	- текущая версия ноды проверяется командой `node -v`;
4. Установка нового проекта Laravel:
	- команда `laravel new program-name`;
	- установить все npm-зависимости командой `npm i && npm run build`
	- после установки нужно запустить проект командой `composer run dev` (включающий `php artisan serve` - аналог `npm run dev` для Node.js).
	- запуск проекта командой `composer run dev` включает в себя такой скрипт:
		```json
		"scripts": {
			"dev": [
				"Composer\\Config::disableProcessTimeout",
				"npx concurrently -c \"#93c5fd,#c4b5fd,#fdba74\" \"php artisan serve --port=3600\" \"php artisan queue:listen --tries=1\" \"npm run dev -- --host\" --names='server,queue,vite'"
			],
		}
		```
		- чтобы дать возможность запускать сайт с внешних устройств, мы добавили в команду `npm run dev -- --host` параметр хост;
		- для запуска проекта на конкретном порту, добавили в команду `php artisan serve --port=3600` параметр порт, чтобы несколько проектов ларавел запускались на разных серверах - это будет порт для запуска ПРИЛОЖЕНИЯ, данная команда обслуживает работу всего laravel-бэкенда;
		- для разворачивания уникального vite-сервера, который занимается адаптацией vue-фронтенда, нужно указать порт либо в файле `vite.config.ts`:
			```ts
			import { defineConfig } from 'vite'
			
			export default defineConfig({
			  server: {
				host: '127.0.0.1', // чтобы доступ был с любых адресов
				port: 5173, // нужный вам порт
			  },
			})
			```
			либо в команде `npm run dev -- --port 5173 --host` указать номер порта

### Настройки конфигураций проекта
#####  1. Добавление алиасов
Алиасы нужны для упрощения импортов нужных компонентов в файлах. Алиасы следует **добавлять в двух местах**:
1. `vite.config.ts` - отвечают за сборку проекта Vite, позволяет правильно отыскать и импортировать нужные компоненты. ==Пример:==
	```ts
	export default defineConfig({
		resolve: {
	        alias: {
	            '@': path.resolve(__dirname, 'resources/js'),
	            '@base': path.resolve(__dirname, 'resources/js/components/base'),
	            '@svg': path.resolve(__dirname, 'resources/assets/svg'),
	            '@css': path.resolve(__dirname, 'resources/css'),
	        },
	    },
	});
	```
   
2. `tsconfig.json` - отвечают за подсветку интерфейса VSCode (визуализация ошибок Typescript/Volar). ==Пример:== 

	```json
	{
		compilerOptions: {
			"paths": {
				"@/*": ["./resources/js/*"],
	            "@base/*": ["./resources/js/components/base/*"],
	            "@svg/*": ["./resources/assets/svg/*"],
	            "@css/*": ["./resources/css/*"],
	        },
		}
	}
	```

Есть еще третий слой - `eslint.config.js`, но он завязан на `tsconfig.json` через плагин `eslint-import-resolver-typescript`, поэтому туда добавлять данные не нужно.
