#route 

1. **Просмотр всех маршрутов** проекта: `php artisan route:list`:
	- если нужно добавить список миддлваров, используется флаг `-v` (либо `-vv` для разворачивания групп миддлваров при их наличии);
	- просмотр рутов, которые начинаются с определенного URI: `--path=api`;
	- спрятать те руты, которые обеспечиваются подключенными плагинами/пакетами: `--only-vendor`
2. **Методы фасада**:
	```php
	Route::view('/page', 'pageFileName', ['param1' => 'paramValue']); // сразу же открывает view, расположенный в директории `/resources/views`
	Route::get('/page', $callback);
	Route::post('/page', $callback);
	Route::put('/page', $callback);
	Route::patch('/page', $callback);
	Route::delete('/page', $callback);
	Route::options('/page', $callback);
	Route::match(['get', 'post'], '/page', $callback); // рут, одинаковый для двух методов - get и post
	Route::any('/page', $callback); // рут для любых методов (следует писать в самом низу, иначе будет перекрывать все последующие варианты)
	```
	  где $callback - это функция с параметрами, выполняющая действия по открытию нужной страницы (например, через хелпер `view(...)`, либо через фасад `Inertia::render(...)`);
3. **Коллбэк** предполагает использование функции, в которую можно передавать как инъекции зависимостей (все, что зарегистрированы в сервис-контейнере), так и динамические параметры, и их порядок такой - *сперва идут инъекции зависимостей, а затем параметры маршрута* в том порядке, в котором они присутствуют в URL (а вот их имена могут быть любыми):
   `(Request $request, string $slug) {...}`:
	- динамические параметры коллбэка могут быть необязательными, в этом случае рендериться будет всегда одна и та же страница, указанная в маршруте, но передаваться в нее будут разные параметры (*обязателен параметр по умолчанию*):
		```php
		Route::get('/user/{name?}', function(?string $name = 'Вася') {...})
		```
	- возможно использование [регулярных выражений](https://laravel.com/docs/12.x/routing#parameters-regular-expression-constraints) для ограничения подходящих маршрутов. Для наиболее популярных ограничений есть хелперы `->where...`;
	- паттерны регулярных выражений можно сохранить глобально, чтобы не добавлять каждый раз в маршруты (например, использование только чисел для всех параметров с именем `$id` в проекте). Нужно [зарегистрировать паттерны](https://laravel.com/docs/12.x/routing#parameters-global-constraints) в `/app/providers/AppServiceProvider.php` в функции `boot()` через метод:
	  ```php
	  Route::pattern('id', '[0-9]+')`
	  ```
4. **Добавление имени маршруту** - использование метода `name`:
	```php
	Route::get(...)->route('route_name');
	```
5. **Группировка маршрутов** позволяет привязать сразу к нескольким маршрутам миддлвары, контроллеры, поддомены и префиксы:
	```php
	Route::controller(Controller::class)->group(function() {
		Route::get(...);
		Route::post(...);
	})
	Route::middleware(['first', 'second'])->group(...);
	Route::domain('{account}.example.com')->group(...);
	Route::prefix('admin')->group(...); // /admin/pageName
	Route::name('admin.')->group(...); // /admin.pageName
	```
6. **Поиск модели** по переданному `slug`:
	- *неявный поиск* - передача в параметре модели из БД, из которой будет производиться автоматический поиск записи по `slug`:
		```php
		use App\Models\User;
		use App\Http\Controllers\UserController;
		
		Route::get('/users/{user}', function (User $user) {
		    return $user->email;
		});
		
		// ! также доступно, если все переходы выполняются из контроллера:
		Route::get('/users/{user}', [UsersController::class, 'show']);
		// ! в контроллере в качестве параметра также используем User:
		public function show(User $user) {
			return view('user.profile', ['user' => $user]);
		}
		
		// ! можно задать поле для фильтрации (по умолчанию id):
		Route::get('/posts/{post:slug}', function (Post $post) {...})
		
		// ! можно связать 2 параметра между собой так, чтобы поиск по второму параметру использовал также первый параметр (двойная фильтрация) через scopeBindings() - при условии, что 2 модели связаны между собой (см. блок с Models):
		Route::get('/users/{user}/posts/{post}', function(User $user, Post $post) {...})->scopeBindings();
		
		// либо вот так для целой группы рутов, но исключая какой-то из них с помощью withoutScopedBingings():
		Route::scopeBindings()->group(function() {
			Route::get(...)->withoutScopedBingings();
		}); 
		```
		Можно задать [изменение поля поиска глобально](https://laravel.com/docs/12.x/routing#customizing-the-default-key-name) для всех запросов указанной модели с помощью функции `getRouteKeyName()` в классе модели;
	- *связывание по enum* - можно создать Enum и т.о. ограничить варианты выбора значений для параметра маршрута:
		```php
		namespace App\Enums;
		enum Category: string {
		    case Fruits = 'fruits';
		    case People = 'people';
		}
		
		use App\Enums\Category;
		Route::get('/categories/{category}', function (Category $category) {
		    return $category->value;
		});
		```
	- явное связывание - указание своего способа фильтрации данных при обращении к модели, добавляется в `/app/providers/AppServiceProvider.php`:
	```php
	use App\Models\User;
	use Illuminate\Support\Facades\Route;
	
	public function boot(): void
	{
	    Route::bind('user', function (string $value) {
	        return User::where('name', $value)->firstOrFail();
	    });
	}
	```
7. **Выполнение функции, если маршрут не найден** (вместо 404 по умолчанию) с помощью функции `missing`:
	```php
	Route::get('/locations/{location:slug}', [LocationsController::class, 'show'])
	    ->name('locations.view')
	    ->missing(function (Request $request) {
	        return Redirect::route('locations.index');
	    });
	```
8. **Fallback-маршруты**. Они срабатывают, когда маршрута с таким наименованием не найдено, и это должно привести к ошибке 404. Важно размещать этот маршрут в конце всех остальных маршрутов, чтобы не было преждевременного перехватывания:
```php
Route::fallback(function () {
    // ...
});
```
9. [**Установка лимитов**](https://laravel.com/docs/12.x/routing#rate-limiting) на совершение запросов в период времени. Позволяет избежать падения сервера при атаках (резком увеличении частоты запросов к серверу). Может отслеживать подключение по коду пользователя или его ip-адресу. Пример использования:
	```php
	use Illuminate\Support\Facades\RateLimiter;
	
	RateLimiter::for('api', function (Request $request) {
	    return Limit::perMinute(60)->by($request->user()?->id ?: $request->ip());
	});
	
	// Назначение middleware
	Route::middleware(['throttle:api'])->group(function () {
	    Route::get('/user', function () {
	        // ...
	    });
	});
	```
9. **Текущий маршрут**:
	```php
	use Illuminate\Support\Facades\Route;
	
	$route = Route::current(); // Illuminate\Routing\Route
	$name = Route::currentRouteName(); // string
	$action = Route::currentRouteAction(); // string
	```
9. **Кэширование и очистка кэша** зарегистрированных маршрутов - для существенного ускорения работы - с помощью команд:
	```bash
	php artisan route:cache
	php artisan route:clear
	```
