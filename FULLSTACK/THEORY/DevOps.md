# 1. Как вообще сайт становится доступным

Начнём с самого фундаментального — **что происходит, когда пользователь вводит домен в браузере**.

---

## 1.1 Полная цепочка запроса

```
Пользователь вводит https://example.com (🔒 SSL (https) 👉 «замочек» в браузере)
        ↓
DNS → узнаём IP
        ↓
Браузер делает HTTP(S)-запрос на IP
        ↓
Запрос приходит на сервер
        ↓
Nginx принимает запрос (входная точка, веб-сервер и reverse proxy)
        ↓
Nginx:
   → либо отдаёт файл
   → либо отправляет в Node.js (бэкенд-сервер, например, Nuxt)
        ↓
Node (Nitro) обрабатывает
        ↓
Ответ возвращается обратно
```

---

## 1.2 Что такое DNS (и как он реально работает)

DNS — это Domain Name System (система доменных имен):

> система, которая переводит доменное имя (example.com) в IP-адрес (например 142.250.74.206)

---

### 🔹 Важный момент: DNS — это не один сервер

Он распределён:

- у браузера есть кэш
- у ОС есть кэш
- у провайдера есть DNS
- есть глобальные DNS-серверы

---

### 🔹 Как происходит запрос

Когда ты вводишь домен:

1. браузер проверяет кэш
2. если нет → идёт в ОС
3. если нет → идёт к DNS провайдера
4. если нет → идёт по цепочке DNS серверов

---

### 🔹 TTL — ключевая проблема

Каждая запись DNS имеет TTL (Time-to-live):

```
example.com → 1.2.3.4 (TTL = 300 секунд)
```

👉 Это значит:

> IP кэшируется на 5 минут

---

### ❗ Реальная проблема (важная для собеса)

Ты поменял сервер:

```
старый IP → не работает
новый IP → уже есть
```

Но пользователь:

```
в кэше → старый IP → ошибка
```

---

👉 И он будет ходить на старый IP, пока TTL не истечёт.

---

### ✔️ Как решают

- заранее уменьшают TTL
- используют CDN (см. ниже)

---

# 3. Nginx — ключевой элемент всей системы

---

## 3.1 Что это такое

Nginx — это:

> веб-сервер и reverse proxy

---

## 3.2 Что значит "слушает порт"

```
listen 80;
listen 443;
```

---

👉 Это значит:

> Nginx принимает запросы, приходящие на эти порты

---

### Пример:

- порт 80 → HTTP
- порт 443 → HTTPS

---

---

## 3.3 Reverse proxy (самое важное)

```
Браузер → Nginx → Node
```

---

👉 Почему не сразу Node?

Потому что Nginx:

- быстрее
- умеет фильтровать (Rate Limiting)
- умеет распределять нагрузку (Load Balancing)

Но если Nginx не установлен, запрос идет сразу на Node.js! Однако надо иметь в виду, что в этом случае требуется указать правильный порт бэкенд-сервера.

---

---

## 3.4 Как Nginx решает, что делать с запросом

Типичный конфиг:

```
location / {  
	try_files $uri @node;
}

location @node {  
	proxy_pass http://localhost:3000;
}
```

---

### Логика:

```
если файл существует → отдать файл
если нет → отправить в Node
```

---

---

## 3.5 Пример

Запрос:

```
GET /logo.png
```

👉 Nginx:

- проверяет файл
- находит
- отдаёт

---

---

Запрос:

```
GET /api/users
```

👉 файла нет → идёт в Node

# 5. Кэширование (очень важный блок)

---

## 5.1 Где вообще есть кэш

```

↓
CDN
↓

↓
Node
↓

↓
Database
```

---

👉 кэш может быть **на каждом уровне**

---

---

## 5.2 Cache-Control

Это заголовок:

> который говорит, как кэшировать ресурс

---

---

## 5.3 Основные директивы

---

### 🔹 max-age

```
Cache-Control: max-age=60
```

👉 хранить 60 секунд

---

---

### 🔹 no-cache

👉 НЕ «не кэшировать»!

👉 означает:

> каждый раз проверять актуальность

---

---

### 🔹 no-store

👉 вообще не сохранять

---

---

### 🔹 immutable

```
Cache-Control: immutable
```

👉 файл никогда не изменится

---

---

## 5.4 Реальные стратегии

---

### Статика (JS, CSS)

```
Cache-Control: public, max-age=31536000, immutable
```

---

👉 потому что:

- есть hash
- файл уникален

---

---

### HTML

```
Cache-Control: no-cache
```

---

👉 чтобы не было устаревших страниц

---

---

### API

---

#### Динамика:

```
Cache-Control: no-store
```

---

#### Частично:

```
Cache-Control: max-age=60
```

# 🎯 Ответы для собеседования

---

## ❓ Как работает сайт

> Пользователь делает запрос, DNS переводит домен в IP, запрос приходит на сервер, где Nginx принимает его и либо отдаёт статические файлы, либо проксирует в Node.js, где приложение обрабатывает запрос и возвращает ответ.

---

---

## ❓ Что такое Nginx

> Это веб-сервер и reverse proxy, который принимает входящие HTTP-запросы, может отдавать статические файлы и перенаправлять динамические запросы к backend.

---

---

## ❓ Что такое CDN

> Это сеть серверов, которая кэширует контент ближе к пользователю, ускоряет загрузку и защищает от атак.

---

---

## ❓ Что такое Redis

> Это in-memory хранилище, используемое как кэш для ускорения работы приложения и снижения нагрузки на базу данных.

---

---

## ❓ Что такое API Gateway

> Это единая точка входа, через которую клиент взаимодействует с backend-сервисами.

---

---

## ❓ Как защитить сайт

> Использовать CDN, rate limiting, firewall, аутентификацию и балансировку нагрузки.
