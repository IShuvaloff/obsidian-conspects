# TypeScript Functions & Modern Syntax

## 1. Optional Parameters

```ts
function greet(name?: string) {
}
```

Внутри `name: string | undefined`.

---

## 2. Default Parameters

```ts
function greet(name = 'Guest') {
}
```

TypeScript выводит `name` как `string`.

---

## 3. Rest Parameters

```ts
function sum(...values: number[]): number {
  return values.reduce((a, b) => a + b, 0)
}
```

---

## 4. Callback Typing

```ts
function processUsers(
  users: User[],
  callback: (user: User) => void
) {
  users.forEach(callback)
}
```

`(user: User) => void` — контракт callback-функции.

---

## 5. Generic Callback: `mapItems`

```ts
function mapItems<T, U>(
  items: T[],
  mapper: (item: T, index: number) => U
): U[] {
  return items.map(mapper)
}
```

- `T` — тип элемента исходного массива;
- `U` — тип элемента результирующего массива;
- `mapper` принимает `T` и индекс;
- `mapper` возвращает `U`;
- `mapItems` возвращает `U[]`.

Важно: `T` и `U` не обязаны быть объектами.

---

## 6. Function Overloads

Без overload:

```ts
function parse(
  value: string | number
): string[] | number[] {
  if (typeof value === 'string') {
    return value.split('')
  }

  return [value]
}
```

Даже при `parse('hello')` возвращаемый тип широкий: `string[] | number[]`.

С overload:

```ts
function parse(value: string): string[]
function parse(value: number): number[]

function parse(
  value: string | number
): string[] | number[] {
  if (typeof value === 'string') {
    return value.split('')
  }

  return [value]
}
```

Теперь:

```ts
const a = parse('hello')
// string[]

const b = parse(42)
// number[]
```

---

## 7. Overload signatures и implementation signature

Порядок обязателен:

1. overload signatures;
2. implementation signature с телом.

```ts
function find(id: number): User
function find(email: string): User

function find(value: number | string): User {
  // implementation
}
```

### Важнейший нюанс

> Implementation signature не является публично доступной сигнатурой вызова.

```ts
function test(value: string): string

function test(
  value: string | number
): string | number {
  return value
}
```

```ts
test('hello') // OK
test(42)      // TypeScript error
```

Хотя implementation принимает `number`.

Формула:

```text
overload signatures
→ публичный контракт

implementation signature
→ внутренняя реализация overload-вариантов
→ напрямую снаружи недоступна
```

---

## 8. Когда overload действительно нужен

Когда тип результата зависит от формы входа:

```ts
function getValue(id: number): User
function getValue(ids: number[]): User[]

function getValue(
  value: number | number[]
): User | User[] {
  // ...
}
```

Если вход `string | number`, а выход всегда один и тот же `User`, overload обычно не нужен.

---

## 9. TypeScript overload vs JavaScript

TypeScript overload — compile-time описание нескольких допустимых способов вызова одной runtime-функции.

В чистом JavaScript повторное объявление одноимённых функций не является перегрузкой в стиле Java/C#/C++.

---

## 10. `as`

`as` — type assertion.

```ts
const user = data as User
```

Смысл: «считай это значением типа `User`; ответственность беру на себя».

Это не runtime validation.

---

## 11. `satisfies`

Проверяет соответствие контракту, но сохраняет более точный inferred type.

```ts
type Role = 'admin' | 'user'

const permissions = {
  admin: ['read', 'write'],
  user: ['read']
} satisfies Record<Role, string[]>
```

Полезно для:

- конфигов;
- справочников;
- route maps;
- feature flags.

---

## 12. `: Type` vs `satisfies` vs `as`

### Type annotation

```ts
const config: Config = {
  defaultTheme: 'light',
  allowSwitch: true
}
```

Переменная имеет именно контракт `Config`.

### `satisfies`

```ts
const config = {
  defaultTheme: 'light',
  allowSwitch: true
} satisfies Config
```

Проверяет контракт, но сохраняет более точный inferred type.

### `as`

```ts
const config = data as Config
```

Assertion: разработчик утверждает тип.

Формула:

```text
: Type -> переменная имеет этот контракт
satisfies Type -> проверить контракт, сохранить inference
as Type -> assertion
```

---

## 13. Trade-off `satisfies`

```ts
type Theme = 'light' | 'dark'

const config = {
  defaultTheme: 'light',
  allowSwitch: true
} satisfies {
  defaultTheme: Theme
  allowSwitch: boolean
}
```

`defaultTheme` может остаться узким типом `'light'`.

Если значение должно свободно меняться между `'light'` и `'dark'`, лучше обычная annotation:

```ts
type Config = {
  defaultTheme: Theme
  allowSwitch: boolean
}

const config: Config = {
  defaultTheme: 'light',
  allowSwitch: true
}

config.defaultTheme = 'dark'
```

`satisfies` не является заменой любой type annotation.

---

## Быстрая interview-шпаргалка

```text
optional -> parameter?: T
default -> parameter = value
rest -> ...values: T[]
callback -> типизируем контракт функции
overload -> несколько публичных сигнатур одной runtime-реализации
implementation signature -> тело реализации, не публичная overload-сигнатура
as -> assertion
satisfies -> проверка контракта без потери точного inference
```
