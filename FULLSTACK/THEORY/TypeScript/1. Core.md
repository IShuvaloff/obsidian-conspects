# TypeScript Core

## 1. `any`, `unknown`, `void`, `never`

### `any`
Фактически отключает проверку типов.

```ts
let value: any
value.foo.bar()
value()
value.toUpperCase()
```

> **Interview-формулировка:** `any` позволяет работать со значением без типовых ограничений, но тем самым теряется большая часть преимуществ TypeScript.

### `unknown`
Безопасная альтернатива `any`.

```ts
function handle(value: unknown) {
  if (typeof value === 'string') {
    console.log(value.toUpperCase())
  }
}
```

До narrowing использовать значение как строку нельзя.

Конструкция:

```ts
value as unknown as SomeType
```

— это обход ограничений системы типов, а не основное назначение `unknown`.

### `void`
Означает отсутствие полезного возвращаемого значения функции.

```ts
function logMessage(message: string): void {
  console.log(message)
}
```

### `never`
Означает невозможное значение или выполнение, которое не завершается нормальным возвратом.

```ts
function fail(message: string): never {
  throw new Error(message)
}
```

```ts
function infiniteLoop(): never {
  while (true) {}
}
```

### Exhaustive checking через `never`

```ts
type Status = 'loading' | 'success' | 'error'

function handle(status: Status) {
  switch (status) {
    case 'loading':
      break
    case 'success':
      break
    case 'error':
      break
    default: {
      const exhaustive: never = status
      return exhaustive
    }
  }
}
```

Если позже добавить `'cancelled'` и забыть обработать этот case, TypeScript покажет ошибку в `default`.

## 2. `type` и `interface`

Оба умеют описывать объектные структуры.

```ts
interface User {
  id: number
  name: string
}
```

```ts
type User = {
  id: number
  name: string
}
```

### Когда особенно удобен `type`

```ts
type Status = 'loading' | 'success' | 'error'
type UserId = number
type Point = [number, number]
```

Также удобен для композиции:

```ts
type Admin = User & {
  permissions: string[]
}
```

### Когда особенно удобен `interface`

Объектные контракты и расширение:

```ts
interface Admin extends User {
  permissions: string[]
}
```

### Declaration merging

```ts
interface User {
  id: number
}

interface User {
  name: string
}
```

Результат:

```ts
interface User {
  id: number
  name: string
}
```

Если одноимённое поле имеет несовместимый тип, будет TypeScript-ошибка на этапе type checking.

**Interview-формулировка:** для обычных объектных моделей оба подхода допустимы; `type` особенно нужен для unions, tuples и композиции, а `interface` — для расширяемых объектных контрактов и declaration merging.

---

## 3. Tuple

Tuple — массив фиксированной структуры, где тип известен для каждой позиции.

```ts
const user: [number, string] = [42, 'Alex']
```

Здесь индекс `0` — `number`, индекс `1` — `string`.

---

## 4. Type alias

Alias — новое имя существующего типа:

```ts
type UserId = number
type Email = string
```

Это не создаёт новый runtime-тип.

---

## 5. Union и Intersection

### Union — `|`

```ts
type ID = string | number
```

Формула: `A | B` = A ИЛИ B.

### Intersection — `&`

```ts
type HasId = { id: number }
type HasName = { name: string }

type User = HasId & HasName
```

Формула: `A & B` = A И B.

### Невозможные intersection-типы

```ts
type Impossible = string & number
```

Практически это `never`.

---

## 6. Narrowing

Narrowing — сужение широкого типа до более конкретного на основании runtime-проверки.

```ts
function print(value: string | number) {
  if (typeof value === 'string') {
    value.toUpperCase()
  } else {
    value.toFixed(2)
  }
}
```

Основные способы:

- `typeof`
- `instanceof`
- `in`
- проверка `null` / `undefined`
- discriminated union

### `instanceof`

Работает с runtime-классами/конструкторами.

```ts
class User {}

if (value instanceof User) {
}
```

С `type` и `interface` использовать нельзя: они исчезают после компиляции.

### `in`

```ts
if ('permissions' in person) {
}
```

`in` — JavaScript runtime-оператор. TypeScript использует результат для narrowing.

Если свойство есть у всех вариантов union, оно не поможет различить типы.

## 7. Discriminated Union

```ts
type RequestState =
  | { status: 'loading' }
  | { status: 'success'; data: string[] }
  | { status: 'error'; error: Error }
```

```ts
function render(state: RequestState) {
  if (state.status === 'success') {
    console.log(state.data)
  }

  if (state.status === 'error') {
    console.log(state.error)
  }
}
```

Поле `status` — discriminator.

Типичные применения:

- loading / success / error
- события
- варианты компонентов
- state machines
- API Result pattern

---

## 8. Type Guard

Type guard — runtime-проверка, которая помогает TypeScript выполнить narrowing.

```ts
interface User {
  id: number
  name: string
}

function isUser(value: unknown): value is User {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value &&
    'name' in value &&
    typeof value.id === 'number' &&
    typeof value.name === 'string'
  )
}
```

`value is User` — type predicate.

---

## 9. Structural Typing

TypeScript в основном использует структурную типизацию: важна форма типа, а не его имя.

```ts
interface User {
  id: number
  name: string
}

const employee = {
  id: 42,
  name: 'Alex',
  department: 'Frontend'
}

const user: User = employee
```

Это допустимо, потому что `employee` содержит всё, что требует `User`.

### Excess Property Checking

```ts
const user: User = {
  id: 42,
  name: 'Alex',
  department: 'Frontend'
}
```

Для свежего object literal TypeScript выполняет дополнительную проверку лишних свойств и может ругаться на `department`.

Но через промежуточную переменную применяется обычная structural compatibility.

## Быстрая interview-шпаргалка

```text
any -> отключает type safety
unknown -> перед использованием нужен narrowing
void -> нет полезного возвращаемого значения
never -> невозможное значение / нормального возврата нет
union | -> OR
intersection & -> AND
narrowing -> сужение типа
type guard -> runtime-проверка для narrowing
discriminated union -> union с discriminator-полем
structural typing -> важна структура типа
```
