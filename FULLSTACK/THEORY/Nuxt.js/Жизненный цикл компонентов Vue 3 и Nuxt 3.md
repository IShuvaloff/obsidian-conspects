#lifecycle #vue #nuxt #ssr #hydration #hooks

**Жизненный цикл компонента** — это последовательность этапов, через которые проходит компонент с момента создания до полного удаления из памяти.

На каждом этапе Vue предоставляет специальные хуки (Lifecycle Hooks), позволяющие выполнять собственный код в строго определенный момент работы фреймворка.

Для Vue 3 (Composition API) жизненный цикл удобно разделять на 4 основные фазы:

1. **Инициализация** (Initialization)
2. **Монтирование** (Mounting)
3. **Обновление** (Updating)
4. **Размонтирование** (Unmounting)

---

# Общая схема жизненного цикла

```text
 Создание компонента
         │
         ▼
      setup()
         │
         ▼
  onBeforeMount()
         │
         ▼
 Рендер Virtual DOM
         │
         ▼
Создание реального DOM
         │
         ▼
    onMounted()
         │
         ▼
─────────────────────
    Обновления
─────────────────────
  onBeforeUpdate()
         │
         ▼
   Обновление DOM
         │
         ▼
    onUpdated()
         │
         ▼
─────────────────────
     Удаление
─────────────────────
  onBeforeUnmount()
         │
         ▼
   onUnmounted()
```

# Фаза 1. Инициализация

### Что происходит

Vue создает экземпляр компонента:

- выполняет `<script setup>`
    
- создает `ref`
    
- создает `reactive`
    
- создает `computed`
    
- создает `watch`
    
- создает `watchEffect`
    
- выполняет composables
    

По сути весь код внутри:

```ts
<script setup>
</script>
```

является фазой инициализации.

В Composition API отдельного хука для этого этапа нет.

---

### Что доступно

Можно:

```ts
const count = ref(0)
const fullName = computed(...)
```

Можно вызывать:

```ts
useRoute()
useState()
useRuntimeConfig()
useFetch()
useAsyncData()
```

---

### Что недоступно

DOM еще не существует.

Нельзя:

```ts
element.value.offsetWidth
document.getElementById(...)
inputRef.value.focus()
```

---

### Важный нюанс Nuxt

Код внутри `<script setup>` выполняется:

```text
Сервер (SSR)
        +
Клиент (Hydration)
```

То есть дважды.

Поэтому опасно писать:

```ts
const token = localStorage.getItem('token')
// или
window.innerWidth
// или
document.title
```

В SSR получим:

```text
window is not defined
```

---

# Фаза 2. Монтирование

Компонент превращается из JavaScript-объекта в реальный HTML.

---

### onBeforeMount()

Вызывается непосредственно перед вставкой DOM.

```ts
onBeforeMount(() => {...})
```

Используется редко.

Практических сценариев немного.

---

### onMounted()

Самый важный хук жизненного цикла.

```ts
onMounted(() => {...})
```

Вызывается после того, как:

- компонент смонтирован
    
- DOM создан
    
- дочерние компоненты смонтированы
    

---

### Что здесь можно делать

Работа с DOM:

```ts
inputRef.value.focus()
```

Получение размеров:

```ts
element.value.offsetWidth
```

Работа с браузерными API:

```ts
window
document
localStorage
sessionStorage
navigator
```

Инициализация библиотек:

```text
Swiper
Leaflet
Chart.js
Google Maps
ResizeObserver
IntersectionObserver
```

---

### ⚠️Что важно помнить

#### mounted выполняется только в браузере

На сервере он никогда не вызывается.

Это один из самых популярных вопросов на собеседованиях по Nuxt.

```text
SSR
    └─ mounted НЕ вызывается

Browser
    └─ mounted вызывается
```

---

### ❌Частая ошибка

Плохо:

```ts
onMounted(async () => {
  await loadUsers()
})
```

Если данные нужны для SSR.

Почему плохо:

```text
Сервер
    ↓
Пустой HTML

Клиент
    ↓
mounted
    ↓
fetch
    ↓
данные
```

Теряются преимущества SSR.

Для загрузки данных страницы нужно использовать:

```ts
await useFetch(...)
// или
await useAsyncData(...)
```

---

# Фаза 3. Обновление

Каждый раз, когда меняются реактивные данные:

```ts
count.value++
```

Vue запускает процесс обновления.

---

## Что происходит внутри

```text
     Изменился ref
           │
           ▼
 Vue пометил компонент
           │
           ▼
Создал новый Virtual DOM
           │
           ▼
     Выполнил diff
           │
           ▼
      Обновил DOM
```

---

### onBeforeUpdate()

Вызывается перед обновлением DOM.

```ts
onBeforeUpdate(() => {...})
```

Используется редко.

---

### onUpdated()

Вызывается после обновления DOM.

```ts
onUpdated(() => {...})
```

DOM уже содержит актуальные данные.

---

## ⚠️Опасный момент

Нельзя без необходимости изменять реактивные данные внутри `onUpdated`.

Плохо:

```ts
onUpdated(() => {
  count.value++
})
```

Получим:

```text
    updated
       ↓
изменение данных
       ↓
    updated
       ↓
изменение данных
       ↓
    updated
       ↓
      ...
```

Бесконечный цикл.

---

# nextTick()

Очень популярный вопрос на собеседовании.

После изменения реактивных данных DOM обновляется не мгновенно.

Если нужен уже обновленный DOM:

```ts
count.value++

await nextTick()

console.log(element.value.offsetHeight)
```

# Фаза 4. Размонтирование

Компонент удаляется из DOM.

Например:
1. Условное отображение компонента:
```html
<div v-if="false">
```
2. закрытие модального окна
3. смена страницы

---

### onBeforeUnmount()

Компонент еще существует.

Последний шанс получить доступ к DOM.

```ts
onBeforeUnmount(() => {...})
```

---

### onUnmounted()

Компонент уже полностью удален.

```ts
onUnmounted(() => {...})
```

Главное назначение: очистка (**Cleanup**).

# Cleanup

---

### Что обязательно очищать

**Таймеры**:

```ts
const interval = setInterval(...)

onUnmounted(() => {
  clearInterval(interval)
})
```

**Слушатели**:

```ts
window.addEventListener(...)
```

**WebSocket**:

```ts
socket.close()
```

**Observer**:

```ts
observer.disconnect()
```

# Порядок вызова родительских и дочерних компонентов

Очень любят спрашивать на Middle+.

---

### Создание

```text
 Parent setup()
    ↓
   Child setup()
     ↓
  Child mounted()
    ↓
Parent mounted()
```

Вывод:

В `onMounted()` родителя все дочерние компоненты уже существуют.

---

### Удаление

```text
 Parent beforeUnmount()
    ↓
   Child beforeUnmount()
     ↓
  Child unmounted()
    ↓
Parent unmounted()
```

# SSR и Hydration в Nuxt 3

Самая важная часть для собеседований по Nuxt.

---

### Что происходит на сервере

```text
    Request
       ↓
Создание Nuxt App
       ↓
    Plugins
       ↓
  Middleware
       ↓
    setup()
       ↓
  useFetch()
       ↓
  SSR Render
       ↓
      HTML
```

---

### Что происходит в браузере

```text
 Получили HTML
       ↓
  Загрузили JS
       ↓
Повторный setup()
       ↓
   Hydration
       ↓
   mounted()
```

---

# Что такое Hydration

**Hydration** — процесс "оживления" HTML, пришедшего с сервера.

Vue НЕ создает DOM заново.

Он:

```text
          Получает HTML
                 ↓
Создает виртуальное дерево компонентов
                 ↓
       Сравнивает его с HTML
                 ↓
        Подключает события
                 ↓
       Делает DOM реактивным
```

---

# Что выполняется на сервере и клиенте

|Код|SSR|Browser|
|---|---|---|
|`<script setup>`|✅|✅|
|`setup()`|✅|✅|
|`computed`|✅|✅|
|`watch`|✅|✅|
|`watchEffect`|✅|✅|
|`useFetch()`|✅|✅|
|`useAsyncData()`|✅|✅|
|`onBeforeMount()`|❌ Практически не имеет смысла в SSR|✅|
|`onMounted()`|❌|✅|
|`window`|❌|✅|
|`document`|❌|✅|
|`localStorage`|❌|✅|

---

# Где правильно размещать код

|Задача|Инструмент|
|---|---|
|Создать реактивное состояние|`setup`|
|Создать `computed`|`setup`|
|Создать `watch`|`setup`|
|Получить данные страницы|`useFetch` / `useAsyncData`|
|Работать с DOM|`onMounted`|
|Работать с `localStorage`|`onMounted` или `import.meta.client`|
|Работать с `window`|`onMounted` или `import.meta.client`|
|Выполнить side effect|`watch` / `watchEffect`|
|Очистить ресурсы|`onBeforeUnmount` / `onUnmounted`|

# Типичные ошибки на собеседовании

### ❌Ошибка №1

Использовать:

```ts
onMounted(() => {
  loadUsers()
})
```

для данных страницы.

Правильно:

```ts
await useFetch(...)
```

---

### ❌Ошибка №2

Использовать:

```ts
window.innerWidth
```

внутри `<script setup>` без проверки клиента.

---

### ❌Ошибка №3

Считать, что `mounted()` выполняется на сервере.

Не выполняется.

---

### ❌Ошибка №4

Пытаться работать с DOM до `onMounted`.

---

### ❌Ошибка №5

Забывать очищать:

- setInterval
    
- addEventListener
    
- WebSocket
    
- Observer

# Как мыслит Senior

|Вопрос|Решение|
|---|---|
|Нужно вычислить значение?|`computed`|
|Нужно получить данные страницы?|`useFetch` / `useAsyncData`|
|Нужен побочный эффект?|`watch` / `watchEffect`|
|Нужен DOM?|`onMounted`|
|Нужен window/document/localStorage?|`onMounted` / `import.meta.client`|
|Нужно освободить ресурсы?|`onBeforeUnmount` / `onUnmounted`|

Главная идея:

> `setup` отвечает за создание реактивности и подготовку данных.
> 
> `useFetch`/`useAsyncData` отвечают за получение данных в SSR.
> 
> `watch`/`watchEffect` отвечают за побочные эффекты.
> 
> `onMounted` отвечает за работу с браузером и DOM.
> 
> `onUnmounted` отвечает за очистку ресурсов.
> 
> В Nuxt всегда нужно помнить, что `setup` выполняется и на сервере, и на клиенте, а `onMounted` — только в браузере.

# Рассказ про жизненный цикл компонентов Vue/Nuxt (уровень Middle+/Senior)

> **Жизненный цикл компонента** — это последовательность этапов, через которые проходит компонент с момента создания до удаления из памяти. В Composition API его удобно разделить на четыре основные фазы: инициализация, монтирование, обновление и размонтирование.

### 1. Инициализация

> На этапе инициализации выполняется `setup()` (или код внутри `<script setup>`). Здесь создается всё реактивное состояние: `ref`, `reactive`, `computed`, `watch`, `watchEffect`, вызываются composables и подготавливаются данные. При этом DOM еще не существует, поэтому работать с элементами страницы на этом этапе нельзя.

### 2. Монтирование

> Затем Vue создает Virtual DOM, вычисляет изменения и вставляет реальные DOM-элементы в документ. После этого вызывается `onMounted()`. Это основной хук для работы с браузером: здесь безопасно обращаться к DOM, использовать `window`, `document`, `localStorage`, измерять размеры элементов или инициализировать сторонние библиотеки.

### 3. Обновление

> При изменении реактивных данных Vue запускает новый цикл обновления: создает новое виртуальное дерево, сравнивает его с предыдущим через алгоритм diff и изменяет только те части DOM, которые действительно изменились. Для этого этапа существуют `onBeforeUpdate()` и `onUpdated()`, хотя на практике они используются значительно реже, чем `watch` или `computed`.

### 4. Размонтирование

> Когда компонент удаляется, вызываются `onBeforeUnmount()` и `onUnmounted()`. Обычно здесь освобождают ресурсы: очищают таймеры, снимают глобальные обработчики событий, закрывают WebSocket-соединения и другие внешние подписки.

## Если разговор идет про Nuxt

> В Nuxt появляется дополнительный аспект — SSR и гидратация. Очень важно понимать, что код внутри `setup()` выполняется и на сервере, и на клиенте. Поэтому в `setup()` нельзя без проверки обращаться к `window`, `document` или `localStorage`.

> После серверного рендера браузер получает готовый HTML, затем Vue выполняет гидратацию — не создает DOM заново, а "оживляет" уже существующий HTML, подключая реактивность и обработчики событий. Только после завершения гидратации вызывается `onMounted()`, поэтому этот хук существует исключительно в браузере.

---

## Если интервьюер хочет услышать инженерное понимание

> Я воспринимаю жизненный цикл не как набор хуков, а как разделение ответственности.

- `setup()` — создание состояния и подготовка данных.
- `useFetch`/`useAsyncData` — получение данных страницы в Nuxt с поддержкой SSR.
- `computed` — вычисление производных данных.
- `watch`/`watchEffect` — выполнение побочных эффектов.
- `onMounted()` — работа с браузерным API и DOM.
- `onUnmounted()` — освобождение ресурсов.

> Такое разделение делает код более предсказуемым и соответствует архитектуре Vue и Nuxt.
