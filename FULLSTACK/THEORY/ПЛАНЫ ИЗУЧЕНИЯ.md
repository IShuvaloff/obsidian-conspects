## 04. API, безопасность и интеграции

**Статус:** изучать по мере нужд Laravel-проекта.

- ⭕ HTTP: methods, status codes, headers, cookies, CORS, caching
- ⭕ REST API, pagination/filtering/sorting, versioning, OpenAPI/Swagger
- ⭕ идемпотентность и `Idempotency-Key`
- ⭕ authentication/authorization, JWT — после понимания session/Sanctum
- ⭕ OAuth 2.0, OpenID Connect, PKCE — когда появится реальная внешняя интеграция
- ⭕ платежи: webhook, подпись запросов, повторная доставка, идемпотентность
- ⭕ Telegram bot/webhook, email и другие уведомления
- ⭕ WebSocket: realtime-модель, presence, чат ученик ↔ преподаватель, Laravel broadcasting
- ⭕ Redis: cache, sessions, queues, TTL, Pub/Sub
- ⭕ мониторинг, structured logging, error tracking
- ◻️ GraphQL — язык запросов для API и server runtime; будущая тема, не «NoSQL-фреймворк»
- ◻️ gRPC — RPC-подход для сервисов; будущая тема, не замена REST по умолчанию

## 06. Качество: тестирование, performance, accessibility

**Статус:** обязательный следующий трек сразу после устойчивой базы Laravel и завершения backend pet-проекта.

- ⭕ зачем тестировать: confidence, regression prevention, границы ответственности
- ⭕ unit tests: чистая логика, services, composables, helpers
- ⭕ integration / feature tests: Laravel HTTP, database, queues, auth
- ⭕ component tests: Vue components, props/events/slots, state и user behavior
- ⭕ E2E: критические пользовательские сценарии в реальном браузере
- ⭕ test pyramid и разумный баланс: не «тестировать всё одинаково»
- ⭕ fixtures, factories, mocks/stubs/fakes, test database, isolation
- ⭕ Vitest + Vue Test Utils; Laravel PHPUnit или Pest; Playwright
- ⭕ CI: запуск тестов, lint/typecheck/build до delivery
- ⭕ web performance, accessibility и security checks как часть качества
- 🟡 [[Nuxt.js/Storybook - тестирование|Storybook]] — материал подготовлен; предстоит изучить создание, документацию и interaction-тесты UI в изолированной среде

## 07. Delivery: Git, Docker, Linux, NGINX, CI/CD

**Статус:** обязательный прикладной трек. Уже есть первый реальный Docker + NGINX deployment; развиваем через повторение на новых проектах.

- ✅ [[Docker/Deploy Tutorial|Первый Docker deploy Nuxt-проекта]]
- ✅ базовая связка: DNS → NGINX → контейнер → Nuxt
- ⭕ Linux: filesystem, users/groups, SSH keys, permissions, systemd, logs
- ⭕ Docker: images, containers, networks, volumes, Compose, healthchecks, multi-stage builds
- ⭕ Node без Docker: Node LTS, process manager (PM2), env, restart, logs
- ⭕ NGINX: reverse proxy, virtual hosts, headers, static files, WebSocket proxying
- ⭕ TLS: Certbot, renewal, безопасные headers
- ⭕ secrets и environment configuration; `.env` не в Git
- ⭕ PostgreSQL in production: private network, backups, restore drill
- ⭕ CI/CD: GitLab CI — test → build image → registry → controlled deploy → rollback
- ⭕ observability: logs, health checks, monitoring, alerts

## 08. Future: Node.js / Fastify / Nest.js / Prisma

**Статус:** не изучать параллельно с Laravel без конкретной причины.

- ⭕ Node.js runtime: process, filesystem, streams, HTTP, Node-specific event loop
- ⭕ Fastify: API fundamentals и OpenAPI integration
- ⭕ Nest.js: modules, controllers, providers, DI, guards, pipes, interceptors, middleware
- ⭕ Nest modular architecture
- ⭕ Prisma: models, migrations, relations, transactions, pagination, query optimization

## Временно отложено

- ◻️ Python / FastAPI — не входит в текущую траекторию; возвращаться только при конкретной рабочей потребности.
- ◻️ GraphQL, gRPC, class-based TS/OOP — не обязательны до укрепления текущего основного стека.

## Правило приоритета

```text
Vue/Nuxt + JavaScript/TypeScript
        ↓
Laravel + PostgreSQL pet-project
        ↓
API / integrations / WebSocket по требованиям проекта
        ↓
Testing + CI
        ↓

        ↓
Future: Node / Fastify / Nest / Prisma
```
