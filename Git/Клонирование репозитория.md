#ssh #git-clone #ssh-keygen

Можно клонировать репозиторий с сервера GitHub/GitLab минимум двумя способами (через консоль):
1. через ==**ssh-ссылку**== - так проще, [порядок действий](https://docs.gitlab.com/16.7/ee/user/ssh.html) таков:
	1. проверить наличие созданного ранее и активного ssh-ключа в директории по умолчанию C:/Users/iashu/.ssh^[должно быть 2 файла: стандартный (private) и публичный ключ, название которого аналогично названию стандартного ключа, но с постфиксом .pub]:
	   
	   ![[Pasted image 20240111203909.png]]
	   
	2. если ключей нет требуется создать новый ключ:
		* открыть терминал;
		* ввести команду `ssh-keygen` (в этом случае будет создан ключ в кодировке RSA), но можно выбрать и определенную кодировку командой `ssh-keygen -t ed25519 -C 'ssh-key-name'` (для кодировки ED25519);
		* выполнить по порядку все предлагаемые действия;
	3. скопировать содержимое публичного ключа и вставить его в блок SSH в настройках профиля на GitHub/GitLab. Обязательно указать срок действия:
	   
	   ![[Pasted image 20240111204613.png]]
	   ![[Pasted image 20240111204720.png]]

	4. теперь один и тот же ключ сохранен и на гитлабе, и на компьютере, поэтому можно скопировать SSH-ссылку с репозитория:
	   
	   ![[Pasted image 20240111204954.png]]
	   
	5. вызвать команду клонирования репозитория в VSCode внутри директории, куда нужно импортировать папку с содержимым репозитория:
	   
		```shell
		git clone git@git.gromitsoft.ru:tds/front.git
		```
	   
2. через ==**https-ссылку**==. Отличие в том, что здесь при попытке запуллить данные с сервера (и запушить тоже) VSCode будет требовать *аутентификацию с вводом логина и пароля*. Но можно сохранить свои аутентификационные данные в [хранилище учетных данных](https://git-scm.com/book/ru/v2/%D0%98%D0%BD%D1%81%D1%82%D1%80%D1%83%D0%BC%D0%B5%D0%BD%D1%82%D1%8B-Git-%D0%A5%D1%80%D0%B0%D0%BD%D0%B8%D0%BB%D0%B8%D1%89%D0%B5-%D1%83%D1%87%D1%91%D1%82%D0%BD%D1%8B%D1%85-%D0%B4%D0%B0%D0%BD%D0%BD%D1%8B%D1%85).

	Если при вводе логина и пароля вылетает ошибка вида:
	![[Pasted image 20240111203339.png]]
	следует проверить возможность сохранения новых ключей в "Диспетчере учетных данных" Windows, т.к. при использовании http-ссылки и вводе логина с паролем Windows автоматически пытается сохранить учетные данные:
	![[Pasted image 20240111205254.png]]
	Для проверки ошибки нужно попробовать создать новые учетные данные. Если возникает ошибка создания, значит диспетчер переполнен и нужно удалить лишние записи. Тогда все заработает.
